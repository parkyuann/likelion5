# 기존 크롤링 대비 보완된 정보 정리 (T2-1 · T2-2)

> 실전2(검색)를 위해 기존 파이프라인을 확장하면서 **KOSIS 표에서 추가로 확보한 정보**와
> **검색용 문서 구조 개선**을 T2-1 / T2-2 항목 기준으로 정리한다.
> 신규 코드: `kosis_meta_enricher.py`, `kosis_catalog_builder.py`, `kosis_indexer.py`
> 원본(`kosis_tree_crawler.py`, `build_kosis_catalog.py`)은 수정하지 않았다.

---

## 0. 한눈에 보기

| 구분 | 기존 (트리 + catalog_v1) | 보완 후 (enriched) | 관련 태스크 |
|---|---|---|---|
| 표 목록(이름·경로) | ✅ 있음 | ✅ 그대로 | — |
| **차원명 / 차원값** | ❌ 없음 | ✅ 추가 | T2-1 |
| **항목명** | ❌ 없음 | ✅ 추가 | T2-1 |
| **단위(units)** | ❌ 없음 | ✅ 추가 | T2-2 |
| **시점(period)** | ❌ 없음 | ✅ 추가 | T2-2 |
| 검색 문서 구조 | 1필드 혼합(`document_text`) | 2필드 분리 + payload | T2-1 / T2-2 |

원본 트리(`kosis_table_tree.json`)의 표 1개가 가진 필드는 `org_id · tbl_id · tbl_nm ·
stat_id · path`뿐이다 — **"어떤 표가 있나"(목록)** 수준. 아래는 여기에 더한 것들이다.

## 1. T2-1에서 보완한 것 — 표 문서화 분리

T2-1 정의:
- `doc_meta_text` = tbl_name + category_path + **핵심 차원명** (임베딩 대상, 짧게)
- `doc_item_index` = **전체 항목명 · 차원값** (BM25 / 메타 필터 전용)

이를 위해 다음을 KOSIS `getMeta ITM` API로 표마다 추가 크롤링했다.

| 보완 항목 | 무엇인가 | 예시 (누적 혼인 비율) | 들어가는 필드 |
|---|---|---|---|
| **차원명** | 표를 쪼개는 축의 이름 | `성별`, `년생별` | `doc_meta_text` (짧게) |
| **차원값** | 그 축 안의 값 전부 | `전체/남자/여자`, `1983~1995` | `doc_item_index` (전부) |
| **항목명** | 표가 측정하는 값의 종류 | `비율` | `doc_item_index` |

핵심 규칙: **차원명은 `doc_meta_text`, 차원값은 `doc_item_index`로 분리**한다.
차원값은 표당 수백~수만 개(예: 읍면동 6천 개)라 임베딩에 넣으면 표의 정체가 목록에 묻히고
임베딩 토큰 한도(8,192)도 넘긴다. 반대로 BM25에는 "종로구" 같은 토큰이 있어야 매칭되므로 넣는다.

**기존 `document_text`의 문제** (개선 전):
```
"누적 혼인 비율 101 2025010 인구 인구동태패널통계 혼인·출산 비율"
              ▲ID숫자(임베딩 노이즈)   ▲경로만, 차원·항목 없음
```
dense 임베딩과 sparse가 한 필드를 공유해 요구가 상충했고, ID 숫자가 노이즈로 섞였다.

**보완 후** (같은 표):
```
doc_meta_text  : 누적 혼인 비율 | 인구 > 인구동태패널통계 > 혼인·출산 비율 | 성별, 년생별
doc_item_index : 비율 전체 남자 여자 1983 1984 ... 1995
```

## 2. T2-2에서 보완한 것 — 색인 메타데이터

T2-2 정의: 색인 시 metadata로 `org_id, period_types, dimensions, units, latest_period` 등을
payload에 저장. 이를 위해 아래를 추가 확보했다.

| 보완 항목 | 무엇인가 | KOSIS API | 예시 | 용도 |
|---|---|---|---|---|
| **units** | 단위 | `getMeta ITM` 우선, 없으면 `getMeta UNIT` | `건`, `%`, `백만원` | 건수 vs 비율 구분 필터 |
| **period_types** | 수록주기 | `getMeta PRD` | `[월, 년]` | 월간/연간 필터 |
| **latest_period** | 최신 시점 | `getMeta PRD` | `2026.06` | 최신성·구판/신판 구분 |
| **dimensions** | 차원명 + 값 개수 | `getMeta ITM` | `시도별(18), 품목별(151)` | 메타 필터 |

### units(단위) 처리 — 조건부 호출
- 단위는 대부분 `ITM` 응답의 항목 행(`UNIT_NM`)에 함께 온다.
- 그러나 '비율·지수'처럼 항목이 단일한 표는 `ITM`에 단위가 비어 오고, 단위가 `getMeta UNIT`에만 있다
  (예: `누적 혼인 비율` → ITM 단위 없음, UNIT=`%`).
- 그래서 **ITM에서 단위를 얻으면 UNIT을 생략하고, 못 얻은 표만 UNIT을 추가 호출**한다(조건부).
  `unit_source` 필드로 출처(itm/unit/none)를 기록한다.
- 주의: ITM 단위는 **항목별(완전)**, UNIT 단위는 **표 대표(단일·때론 없음)**라 ITM을 우선한다.

### 색인 구조 (T2-2)
표 하나를 Qdrant에 3갈래로 저장한다.

| 종류 | 재료 | 검색 방식 |
|---|---|---|
| dense | `doc_meta_text` 임베딩(HCX, 1024차원) | 의미 검색 |
| sparse | `doc_item_index` BM25 | 키워드 검색 |
| payload | `org_id, units, period_types, latest_period, dimensions` | 메타 필터 |

> 단위·시점은 **벡터가 아니라 payload(필터)**에 넣는다 — "% 표만" 같은 조건으로 후보를 좁히는 용도.

### 호출 비용
- 표당 API 호출: `ITM`(1) + `PRD`(1) + `UNIT`(0~1 조건부) = **2~3회**.
- 전체 265,094표 기준 약 60시간 (분당 200건 제한). 트리 크롤링(카테고리당 1회, 표 묶음 수신)과
  달리 **표당 개별 호출**이라 시간이 크다.

## 3. sample600 표본이란 무엇인가

전체 크롤링(265,094표, 약 60시간)에 앞서, 파이프라인 검증과 팀 공유를 위해 뽑은 **표본**이다.

| 항목 | 내용 |
|---|---|
| **크기** | 600개 표 |
| **추출 방식** | 30개 대분류(top category) × 각 **20개** |
| **무작위성** | 각 대분류 '안'에서 랜덤 추출 (앞 순서 대표 표 편향 방지) |
| **재현성** | 시드(seed) 42 고정 — 다시 뽑아도 같은 600개 |
| **파일** | `kosis_table_meta_enriched_sample600.jsonl`(원본), `kosis_catalog_enriched_sample600.jsonl`(카탈로그) |

### 왜 이렇게 뽑았나
- 이전 표본(인구만 515개)은 한 분야에 몰려 전 분야 검색 성능을 볼 수 없었다.
- 30개 대분류(인구·노동·물가·금융·지역통계 …)에서 균등하게 뽑아 **전 분야 커버리지**를 확보했다.
- 지역통계(V)는 실제로 전체의 60%지만, 표본에서는 다른 분야와 동일하게 20개만 뽑았다
  (표 개수 비례가 아니라 **대분류당 균등**). 큰 분야가 표본을 독점하지 않게 하기 위함.

### 표본 실측 지표
| 지표 | 값 |
|---|---|
| 총 표 | 600 (30 × 20, 전 대분류 20개씩) |
| 크롤링 성공 | 600 / 600 (실패 0) |
| units 확보 | 438 / 600 (73%) — ITM 312, UNIT 보강 126, 원천에 없음 162 |
| period 확보 | 600 / 600 (100%) |
| `doc_meta_text` 토큰 초과(>8,192) | 0 (최대 117토큰) |

> units가 빈 162개는 크롤러 누락이 아니라 KOSIS 원천에 단위가 없는 표(순위·개수 등)다.
> 단위는 payload 필터라, 없으면 그 필터만 건너뛰며 벡터 검색에는 영향이 없다.

## 5. 요약

- **T2-1**: 트리에 없던 **차원명·차원값·항목명**을 확보하고, 검색 문서를 `doc_meta_text`(임베딩)
  / `doc_item_index`(BM25) 두 필드로 분리했다.
- **T2-2**: **단위(units)·시점(period)**을 추가 확보해 payload 메타 필터로 넣고, dense+sparse+메타로
  Qdrant에 색인했다.
- **sample600**: 30개 대분류 × 20개(랜덤, seed 42)로 전 분야를 균등 커버한 600개 검증 표본.
