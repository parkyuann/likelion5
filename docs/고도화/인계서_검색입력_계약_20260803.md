# 인계서 — 구조화 → 검색 단계 입력 계약

작성일: 2026-08-03
대상: 임베딩 색인·리랭킹·답변 생성 담당
전제: 이 문서는 **구조화 단계가 무엇을 내보내는가**와 **그것이 어디까지 검증됐는가**만
다룬다. 색인 방식이나 리랭커 선택은 여기서 정하지 않는다.

> **2026-08-03 gold v2 정정:** 아래 `0.406`과 확정 gold 32건은 동일 표명 전체
> `table_key`를 동등 정답으로 자동 확장한 v1 결과다. 지역 기본통계와 전국표가
> 섞이는 문제가 확인되어 성능 근거에서 제외했다. exact-key v2에서 현재 확정된
> 10건은 같은 lexical 후보에서 선택된 subset이라 Recall 1.0이지만 선택 편향 때문에
> 성능 지표가 아니다. v2 11개 그룹의 사람 재검토와 독립 test MATCH 15건이 끝나기
> 전에는 어떤 Recall도 채택 하한으로 쓰지 않는다.

---

## 1. 한 문장 요약

기사에서 뽑은 수치 하나마다 **검색 질의 1~3개와 정렬용 필드 6개**를 내보낸다.
질의는 이미 정규화돼 있으므로 그대로 임베딩하면 되고, **연결해서 하나로 만들지
말 것** — 그렇게 하면 성능이 떨어진다는 것이 실측됐다(4.1절).

## 2. 출력 형식

`src/develop/run_layer_stack.py`가 값 하나당 한 행을 낸다.

```jsonc
{
  "article_idx": "1866",
  "value_span_id": "s3:value_unit:12-20",
  "value_text": "1639.8원",
  "value_unit": "원",
  "sentence_text": "이달 첫 주 전국 주유소 휘발유 평균 판매가는 1639.8원이다.",

  "routing_class": "KOSIS_CANDIDATE",   // 이 값만 검색 대상
  "confidence": 1.0,
  "reason": "OFFICIAL_AGGREGATE_REGION",

  "retrieval_queries": [                 // ← 검색이 소비하는 것
    {"role": "indicator", "query": "휘발유 평균 판매가"},
    {"role": "sentence",  "query": "이달 첫 주 전국 주유소 휘발유 평균 판매가는 1639.8원이다."}
  ],

  "retrieval_fields": {                  // ← 표를 고른 뒤 셀 정렬에 쓰는 것
    "indicator": "휘발유 평균 판매가",
    "measurement_type": "LEVEL",         // LEVEL | CHANGE_RATE | CHANGE_POINT | INDEX_LEVEL
    "period": {
      "measurement": {"raw": "이달 첫 주", "absolute": ""},
      "baseline": {"raw": "", "absolute": ""},
      "basis": "NONE"
    },
    "period_raw": "이달 첫 주",          // 전환기 audit alias
    "period_absolute": "2025.05 첫 주", // 전환기 legacy alias
    "population": [], "item": ["휘발유"], "dimension": []
  },
  "field_provenance": { "indicator": "LOCAL", "indicator_projection_marker": false }
}
```

**`routing_class == "KOSIS_CANDIDATE"`인 행만 검색으로 보낸다.** 나머지는 이 단계가
검증 대상이 아니라고 판단한 값이다.

## 3. 질의 계약

| role | 내용 | 비고 |
|---|---|---|
| `indicator` | 정규화된 지표 문자열 | **항상 첫 번째.** 단독 성능이 가장 좋다 |
| `item` | 지표가 담지 못한 품목 | 지표에 이미 포함되면 생략된다 |
| `sentence` | 값이 등장한 원문 문장 | 지표가 놓친 어휘를 담는다 |

**순서가 계약이다.** 질의를 하나만 쓸 수 있으면 첫 번째를 쓰면 되고, 뒤의 것은
대체가 아니라 추가다.

`period`·`population`·`dimension`은 **질의에 넣지 않는다.** 표의 분류축이지 표를
찾는 단서가 아니며, 넣으면 성능이 떨어진다(4.1절).

지표는 다음이 이미 제거된 상태다 — 기간(`이달 첫 주`, `5년 간`), 국내 스코프
(`한국의`), 시점 수식(`초기`), 전망 표지(`미래`). **해외 스코프(`독일`, `OECD`)는
일부러 남긴다** — 지우면 KOSIS가 담지 않는 주장이 검색 가능해 보인다.

## 4. 어디까지 측정됐는가

사람이 판정한 검색 gold **55건**(dev split, 기사 10건)이 있다. 그 중 사람이 표 키까지
확정한 **32건**으로 아래를 쟀다. 나머지 23건은 `표 없음` 11 · `판단 보류` 9 ·
`제안에도 없음` 3이라 자동 채점 대상이 아니다. 후보 생성기는 **어휘 검색(문자 bigram+IDF)**
이므로 전부 **바닥선**이다.

### 4.0 정정 (2026-08-03) — 아래 Recall 수치를 바닥선으로 쓰지 말 것

**4.1~4.2의 Recall은 선택 편향으로 무효다.** 다음 검토에서 확인됐다.

검색 gold 55건은 두 경로로 표가 확정됐다.

```
후보에서 찾음      10건  ← 어휘 검색기의 Top-10에서 골랐다
후보 밖에 있음     22건  ← Top-10에 없어서 사람이 이름을 적었다 (정의상 어휘 miss)
```

**첫 묶음은 어휘 Recall이 정의상 1.000이고, 둘째 묶음은 정의상 0에 가깝다.**
둘을 합친 `13/32 = 0.406`은 어휘 검색기가 스스로 정한 가중치로 자기를 채점한
값이며, 검색기가 더 좋았다면 첫 묶음이 커져서 숫자도 올라간다. **지표가 자기
자신을 측정한다.**

또한 정답 판정을 표명 동일성으로 하던 것도 잘못이었다. `소비자물가지수`는
중앙기관 표와 지자체 표가 같은 이름을 쓰며 서로 교체 가능하지 않다. 현재 계약은
**사람이 확정한 `org_id:tbl_id` 키**만 정답으로 인정하고, 동등한 키는 검토자가
명시할 때만 추가한다.

**편향 없는 측정에 필요한 것** — 검색기 출력과 무관하게 선정한 표본에서, 사람이
후보 목록을 보지 않고(또는 다른 출처의 후보로) 정답 표를 찾아 gold를 만든다.
그 전까지 **어떤 Recall 수치도 성능 주장으로 쓰지 않는다.**

현재 유효한 사실은 둘뿐이다.

- `ceiling_gold_table_name_present = 1.000` — 정답 표는 전부 색인에 존재한다.
  **못 찾는 원인이 색인 부재가 아니라는 것**은 편향과 무관하게 성립한다.
- 4.3절의 어휘 격차 사례는 개별 사례로서 유효하다.

### 4.1 질의를 어떻게 구성하는가 (K=10) — **선택 편향 있음, 4.0절 참조**

**아래 표는 폐기된 v1 동일-표명 동등화 32건의 역사적 진단값이다.** 현재 성능
근거나 임베딩 채택 하한으로 사용하지 않는다.

| 질의 구성 | Recall@10 |
|---|---:|
| `indicator` + item·population을 **연결** | 0.313 |
| `indicator` 단독 | **0.344** |
| 변형을 **따로 실행**하고 각 10개 유지 | **0.406** |
| 변형을 실행 후 **하나의 10개로 융합** (RRF) | 0.344 |
| *상한*: gold 표명 자체로 검색 | **1.000** |

v1은 `소비자물가지수`라는 표명만 같으면 지역 기본통계와 전국 소비자물가조사를 모두
정답으로 처리했다. v2는 사람이 확정한 exact key만 정답이며, 별도 동등 key도 사람이
명시한 경우에만 허용한다. 따라서 아래 차이는 질의 구성 가설을 만드는 참고일 뿐이다.

읽는 법 셋.

1. **연결하면 손해다.** `item`·`population`을 지표에 붙이면 0.344 → 0.313으로
   떨어진다. 표의 분류축 쪽으로 매칭이 끌려간다.
2. **따로 실행하면 이득이 있다.** 0.344 → 0.406. `외국인의 국내 주식 투자 자금
   순유출`처럼 지표가 떨군 어휘를 문장이 갖고 있는 경우다.
3. **그 이득은 후보 예산에서 나온다.** 하나의 Top-10으로 융합하면 RRF여도 0.344로
   돌아간다. 예산이 고정이면 변형은 공짜가 아니다.

### 4.2 후보 예산별 (K를 늘리면)

| K | `indicator` 단독 | 변형 전부 (각 K) |
|---:|---:|---:|
| 5 | 0.344 | 0.344 |
| 10 | 0.344 | 0.406 |
| 20 | 0.375 | 0.406 |
| 50 | 0.375 | 0.406 |
| 100 | 0.469 | 0.469 |

이 표도 v1 역사값이다. exact-key v2와 독립 test gold에서 다시 측정하기 전에는
K 확대 효과나 병목 위치를 확정하지 않는다.

### 4.3 왜 낮은가 — 어휘 격차

| 기사 지표 | 정답 KOSIS 표 | 공유 어휘 |
|---|---|---|
| 1인당 국민소득 | 주요지표(연간지표) | 없음 |
| 근로소득세 수입 | 연도별 국세 징수실적 | 없음 |
| 식품 물가 상승률 | 소비자물가지수 | `물가` |
| 외국인 보유 국내 채권 | 참가자업종별 채권잔고현황 | `채권` |

위 사례는 어휘 격차 가설을 지지하지만 v1 상한 1.000은 exact-key 상한이 아니다.
dense retrieval의 필요성은 유지하되, 개선 폭과 채택 여부는 v2 독립 gold로 판단한다.

## 4.4 어느 필드를 어느 단계가 쓰는가

`period`·`population`·`dimension`을 **질의에서 빼라는 것이지 버리라는 뜻이 아니다.**
쓰는 단계가 다르다.

| 필드 | 소비 단계 |
|---|---|
| `retrieval_queries` | 검색 · 리랭킹 |
| `retrieval_fields.item` / `dimension` / `population` | **조회 계획 생성** (분류축 지정) |
| `retrieval_fields.period.measurement/baseline/basis` | **조회 계획 생성** (한 셀 또는 비교할 두 셀 지정) |
| `retrieval_fields.period_raw` / `period_absolute` | 전환기 audit alias. 신규 소비자는 nested period 사용 |
| `retrieval_fields.measurement_type` | **결정론 비교** (어떤 수식을 쓸지) |
| `value_text` / `value_unit` | **결정론 비교** (기사 수치) |

**후보를 주장에 붙이는 조인 키는 `(article_idx, value_span_id)`다.** 값 하나의 고유
식별자이며 L1이 부여하고 이후 층이 바꾸지 않는다. RAG가 반환한 `table_key`를 입력
후보와 대조하듯, 후보 묶음도 이 키로 원 주장에 되붙일 수 있다.

## 4.5 `PERIOD-PAIR` 결정론 기간 계약 — 2026-08-04 구현

수식으로 대조해 답변에 넘기는 방향은 CLAUDE.md 3절 원칙 5와 같다 — **수치 비교와
증감 계산은 LLM이 아니라 코드가 한다.** 다만 그 수식을 세우기에 현재 출력이
부족하다. dev-12 KOSIS 후보 201건 실측:

| 문제 | 규모 |
|---|---:|
| 증감형(`CHANGE_RATE`/`CHANGE_POINT`)인데 **비교 기준 시점 필드가 계약에 없음** | 50 / 50 |
| `period_absolute`가 날짜로 해소되지 않고 원문을 되풀이 | 증감형 34 / 50, 수준형 80 / 151 |

```
"지난달 생활물가지수가 2.5% 상승했다"
   period=지난달  period_absolute=2025.09
   → 2.5%는 2025.09 값이 아니라 2025.09 대비 2024.09 변화율이다.
     기준 시점 2024.09가 어디에도 없다.

"식품 물가가 전년 동월 대비 3.2% 상승"
   period='전년 동월 대비'  period_absolute='전년 동월 대비'
   → 측정 시점 자체가 없다. 기사 발행일로만 복원 가능하다.
```

**즉 `CHANGE_RATE` 행은 "무엇 대비"가 비어 있어 KOSIS 두 셀을 지정할 수 없다.**
필요한 계약은 단일 `period`가 아니라 다음이다.

```jsonc
"period": {
  "measurement": {"raw": "지난달", "absolute": "2025-09"},
  "baseline":    {"raw": "전년 동월", "absolute": "2024-09"},   // 증감형에서 필수
  "basis": "YOY"   // YOY | MOM | QOQ | PERIOD_TO_PERIOD | NONE
}
```

이 계약은 2026-08-04 L4 결정론 규칙으로 구현됐다. `basis`는 문장의 비교 표현과
이미 결정된 `measurement_type`만 사용한다. 서로 다른 비교축이 한 문장에 함께 있거나
근거가 없으면 `NONE`이다. `전년 동월 대비`처럼 baseline 표현만 있고 측정시점이
없을 때는 기사 발행월을 fallback으로 사용하지만 `measurement.raw`는 빈 값으로 두어
원문에서 나온 것처럼 꾸미지 않는다. `5년 간`은 기간 거리이지 측정 셀이 아니므로
`PERIOD_TO_PERIOD`의 두 셀이 명시되지 않으면 absolute를 비워 둔다.

고정 입력 dev-12 측정 결과:

| 지표 | 전 | 후 |
|---|---:|---:|
| 증감형 측정시점 absolute | 16/50 (0.320) | 24/50 (0.480) |
| 수준형 측정시점 absolute | 61/151 (0.404) | 61/151 (0.404) |
| 증감형 baseline absolute | 0/50 | 13/50 (0.260) |

basis 분포는 전체 KOSIS 후보 201건에서 `NONE 184 / YOY 11 / MOM 2 /
PERIOD_TO_PERIOD 4`다. 증감형 50건만 보면 known basis는 17/50이며, 나머지 33건은
틀린 기준 시점을 만드는 대신 abstain했다. 기존 routed 파일과 `(article_idx,
value_span_id)` 226개가 일치하는 상태에서 라우팅 class/confidence/reason/threshold
변경은 **0건**이다.

기존 `period` 원문을 삭제하지 않기 위해 전환기 alias `period_raw`와
`period_absolute`를 유지한다. 신규 조회 계획 코드는 nested `period`만 소비한다.

## 4.6 최종 결과 객체 — 주장 쪽 계약

사용자용 답변 생성이 받을 결합 객체에서 **첫 항목(`원래 주장`)은 구조화가 공급한다.**
나머지 넷(선택 후보·조회 계획·API 결과·판정 근거)은 하위 단계가 채운다.

```jsonc
"claim": {
  "article_idx": "1866", "value_span_id": "s3:value_unit:12-20",
  "sentence_text": "...", "value_text": "1639.8원", "value_unit": "원",
  "indicator": "휘발유 평균 판매가",
  "measurement_type": "LEVEL",
  "period": { /* 4.5절 형태 */ },
  "source_subtype": "공식집계",
  "routing": {"class": "KOSIS_CANDIDATE", "confidence": 1.0,
              "reason": "OFFICIAL_AGGREGATE_REGION"}
}
```

`routing`을 함께 넘기는 이유는 **`UNVERIFIABLE` 판정의 사유를 답변이 구분해야
하기 때문이다** — 표를 못 찾은 것, 표는 있는데 주기가 안 맞는 것, 애초에 KOSIS
범위 밖인 것은 사용자에게 다르게 설명돼야 한다.

## 5. 알려진 한계 — 넘겨받기 전에 아셔야 할 것

1. **검색 조건의 정확도가 낮다.** 3필드(`indicator`/`measurement`/`period`) 동시
   exact가 **0.118**이다(dev-6, n=102). 값을 버리지는 않지만 붙여주는 조건은 8건 중
   7건이 어딘가 어긋난다. **Recall@K가 낮게 나오면 검색기가 아니라 이것일 수 있다.**
   `indicator` exact 0.216 / relaxed 0.686이므로 완전 오답이 아니라 표현 어긋남이다.
2. **20%는 KOSIS에 표가 없다.** gold 55건 중 11건이 `표 없음`이다(예: 노년 부양비는
   KOSIS에 통계표가 아닌 PDF로만 존재). 구조화·검색이 완벽해도 남는 상한이다.
3. **16%는 표는 맞는데 분류축이 다르다.** `판단 보류` 9건 — 주장은 *분식 가맹점*인데
   표는 *음식점 및 주점업* 단위. 검색이 아니라 셀 정렬(`Task 3-1`) 문제다.
4. **과라우팅이 있다.** 라우팅 precision 0.785(holdout-1). 비통계 기사에서 순번·
   날짜가 후보로 넘어온다. 통계 기사에서는 1.000이다. 잘못 온 값은 `UNVERIFIABLE`로
   끝나는 것이 설계상 정상이다.
5. **레지스트리에 같은 표명이 여러 번 있다.** 기관·연도별 중복이며 후보 10개 중
   고유 표명이 평균 7.2개까지 떨어졌다. 어휘 검색기 쪽은 표명 기준 병합을 넣었고
   병합 수를 `duplicate_tables`로 보고한다. **색인에서도 같은 처리가 필요하다.**

## 6. 성능을 선언할 때의 규칙

CLAUDE.md P0: **gold가 없는 상태의 후보 일치율은 Recall이 아니다.**

- 위 gold 55건은 **dev split**이다. 임계값·가중치를 여기에 맞춰 조정하면 그 순간
  개발셋이 되고, 성능 판정에는 별도 split이 필요하다.
- gold 자체는 사람이 표를 지정한 것이므로 **검색기를 바꿔도 정답은 그대로다.**
  같은 gold로 재측정하는 것 자체는 순환이 아니다.
- `0.406`은 **폐기된 v1 표명 동등화 진단값**이다. exact-key v2 재검토와 독립 test
  gold가 끝나기 전에는 임베딩 채택 하한으로 사용하지 않는다. 현재 10건의 1.0도
  같은 lexical 후보에서 고른 subset이므로 재현 smoke check일 뿐 성능값이 아니다.
