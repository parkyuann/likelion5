# 팀원 공유 파일 가이드 — 기사 주장 구조화·KOSIS 라우팅

작성일: 2026-08-05
대상 브랜치: `ann`
범위: 기사 입력부터 `KOSIS_CANDIDATE` 라우팅 및 검색 질의 생성까지

이 문서는 팀원이 파일을 열기 전에 각 파일의 역할과 실행 순서를 이해하기 위한
인계 문서다. 현재 단계는 KOSIS 통계표 검색·셀 조회·최종 판정까지 완료된 상태가
아니며, `Task 1-1`과 Gate B는 진행 중(`[~]`)이다.

## 전체 실행 흐름

```text
기사 입력
  → L1 값 후보 추출
  → L2 기사 단위 HCX 문맥 구조화
  → L3 값-지표·출처·기간 역할 연결
  → L4 검색·정렬 필드 정규화
  → L5 KOSIS 검증 대상 라우팅
  → retrieval query 생성
```

## 핵심 실행 코드

| 파일 | 역할 | 주요 입력 | 주요 출력 |
|---|---|---|---|
| `src/develop/l1_value_candidates.py` | 기사에서 숫자·단위가 붙은 모든 value candidate와 안정적인 span ID를 추출한다. claim 여부나 지표 의미는 판단하지 않는다. | 기사 본문 | value candidate 목록 |
| `src/develop/l2_segmentation.py` | HCX에 기사 전체 문맥을 주고 문장별 지표 scope, source region, period context를 구조화한다. 프롬프트와 JSON schema도 이 파일에 있다. | 기사 제목·본문, L1 값 후보 | L2 문장 구조화 JSON |
| `src/develop/l2_span_resolver.py` | 사람이 입력하거나 HCX가 반환한 원문 span text를 실제 문장 offset으로 결정론적으로 해석한다. | span text, 문장 | 검증된 span offset |
| `src/develop/l3_role_assignment.py` | L2 layout을 읽어 각 value candidate에 지표·출처·기간 역할을 연결한다. 모델 호출은 없다. | 기사, L2 결과 | 값별 role assignment |
| `src/develop/l4_field_normalization.py` | L3 결과에서 indicator, measurement type, period, population, item, dimension 등 검색·정렬 필드를 코드로 합성한다. | L3 결과, 기사 발행일 | `retrieval_fields` |
| `src/develop/l5_routing.py` | 각 값이 KOSIS 검색으로 갈지 결정한다. 현재 주요 class는 `KOSIS_CANDIDATE`, `OUT_OF_SCOPE`, `NOT_CLAIM`이다. | L3·L4 assignment | routing class, confidence, reason |
| `src/develop/retrieval_query.py` | 라우팅된 값에서 indicator·item·sentence 역할별 검색 질의를 생성한다. | routed assignment | `retrieval_queries` |
| `src/develop/run_l2_segmentation.py` | 기사별 HCX L2 호출을 실행하고 prediction과 manifest를 저장한다. | 기사 JSONL | L2 prediction JSONL, manifest |
| `src/develop/run_layer_stack.py` | 저장된 L2 결과를 사용해 L3→L4→L5→query를 재현한다. L2 이후는 결정론적이다. | 기사 JSONL, L2 JSONL | routed JSONL, summary, evaluation |
| `src/develop/hcx_client.py` | HCX HTTP 호출, structured output 전송, 응답 파싱·retry 등 transport를 담당한다. | prompt, schema, API key | HCX JSON 응답 |
| `src/hcx_claim_experiment.py` | HCX API key 환경변수 조회와 과거 claim extraction 실험 실행 보조를 담당한다. | 실험 입력, 환경변수 | 실험 manifest·prediction |

## 설정 파일

| 파일 | 역할 |

| `configs/hcx_l2_dev6_repeat_matrix_20260805.json` | HCX L2 반복·temperature 탐색 실험 등록값. `development_only`이며 최종 확정 설정으로 간주하지 않는다. |
| `configs/hcx_validation_final_matrix.json` | 과거 validation 실행 matrix |
| `configs/hcx_baseline_20260723.json` | baseline HCX 실험 설정 |
| `requirements.txt` | Python 실행 의존성 |

JSON은 표준 문법상 주석을 넣을 수 없으므로 설정 파일의 의미는 이 문서에서 관리한다.

## 프롬프트 확인 위치

현재 r17 L2의 HCX 프롬프트는 별도 text 파일이 아니라
`src/develop/l2_segmentation.py`에 있다.

- `L2_SYSTEM_PROMPT`: 전체 기사 문맥 구조화 지침
- `L2_SOURCE_SYSTEM_PROMPT`: 출처 region 판단 지침
- `L2_INDICATOR_SYSTEM_PROMPT`: 수치별 지표 판단 지침
- `build_l2_prompt()`: 기사 제목·본문·값 후보를 사용자 prompt로 조립
- `build_l2_schema()`: structured output JSON schema

## 재현 방법

### HCX를 다시 호출하는 경우

```powershell
python -m src.develop.run_l2_segmentation `
  --articles <articles.jsonl> `
  --output <l2_predictions.jsonl> `
  --manifest <l2_manifest.json> `
  --model HCX-007 `
  --temperature 0.1 `
  --top-p 0.8 `
  --max-completion-tokens 4000
```

HCX 호출에는 각자의 환경변수 `NCP_CLOVASTUDIO_API_KEY`가 필요하다. API key는
저장소나 공유 파일에 포함하지 않는다.

### 저장된 L2 결과로 결정론적 하류만 재현하는 경우

```powershell
python -m src.develop.run_layer_stack `
  --articles <articles.jsonl> `
  --l2 <l2_predictions.jsonl> `
  --output <routed.jsonl> `
  --summary <summary.json> `
  --evaluation <evaluation.json>
```

이 실행은 HCX를 호출하지 않고 L3→L5 및 검색 질의 생성을 재현한다.

## 공유 데이터 산출물

| 경로 | 역할 |
|---|---|
| `data/develop/r17_stratum_freeze_20260731/splits/dev/` | 동결된 dev 기사 입력과 split manifest |
| `data/develop/r2_l5_precision_20260804/` | 최신 R2 L5 실행·평가 산출물 |
| `data/develop/r3_full_l2_gold_20260804/` | R3 L2 사람 라벨링 계약·review artifact |
| `data/develop/r17_routing_gold_holdout1_20260803/` | holdout-1 L2·routing 결과와 평가 |

L2 prediction, routed JSONL, manifest, evaluation JSON은 반드시 동일 입력에서 나온
한 세트로 다룬다. 서로 다른 split의 파일을 섞으면 층별 성능 비교가 무효가 된다.

## 현재 상태와 주의사항

- L1 값 후보 추출, L2~L5 구현은 존재한다.
- L2는 HCX 모델 호출이 필요한 층이고, L3 이후는 결정론적 코드다.
- 현재 r17의 최종 routing class는 이전 r16의 4분류(`AMBIGUOUS` 포함)와 계약이 다르다.
- R3 사람 gold와 Gate B 최종 측정 전에는 `Task 1-1`을 완료(`[x]`)로 표시하지 않는다.
- KOSIS 검색 Recall은 독립 gold가 확정되기 전까지 성능 수치로 사용하지 않는다.
- `outputs/`, API 원문, 개인 `.env`, API key는 공유 대상에서 제외한다.
