# 후보 리랭커 (candidate_reranker.py) — 작업 기록

> 실전2 T2-4. 하이브리드 검색 후보 20개를 BGE 리랭커로 재정렬한다.
> 이 문서는 리랭커 작업의 결정·이슈·상태를 계속 기록한다(자동 갱신).

---

## 1. 무엇을 하는가

파이프라인 위치:
```
기사 주장 → [벡터DB 하이브리드 검색] → 후보 20개(hybrid_top20.jsonl)
         → [candidate_reranker.py: BGE 리랭커] → 재정렬된 후보 → (이후 값 조회·검증)
```

- **입력**: `data/hybrid_top20.jsonl` (claim 100개, 각 후보 20개)
- **출력**: `data/hybrid_top20_reranked.jsonl` (입력명 + `_reranked` 자동 생성)
- **코드**: `src/candidate_reranker.py`

리랭커는 (질의, 문서)를 함께 읽어 관련도를 정밀 채점하는 cross-encoder다. 벡터DB가
거칠게 뽑은 후보 20개의 순서를 다시 매겨 정답 표를 위로 끌어올린다.
- 질의 = `claim_text` (뉴스 주장)
- 문서 = 후보의 `tbl_name` (표 이름) — 후보에 표명만 있어서

---

## 2. 모델 선택 — BGE-reranker-v2-m3

| 후보 | 판단 |
|---|---|
| **BGE-reranker-v2-m3** (채택) | 오픈소스·무료·로컬 실행, task 명세 지정, 후보별 점수 제공 |
| NCP CLOVA Reranker | ❌ 이름은 리랭커지만 실제는 **RAG 답변 생성기**. 후보별 점수·순위를 안 줘서 Recall/MRR 계산 불가 |
| ko-reranker / Qwen3-Reranker | 대안(한국어 튜닝/최신). 함수 분리해뒀으니 나중에 교체·비교 가능 |

- 무료(오픈소스), 로컬 실행. 최초 1회 모델 약 2.3GB 다운로드.
- 리랭킹 로직을 `rerank_candidates()` 함수로 분리 → `kosis_retriever.py` 통합·모델 교체 쉽게.

---

## 3. 출력 형식

출력은 입력과 같은 구조인데, `final_candidates`를 리랭커 점수 내림차순으로 재정렬하고
각 후보에 두 필드를 덧붙인다:

| 필드 | 뜻 |
|---|---|
| `rerank_score` | BGE 관련도 점수(0~1, sigmoid 정규화. 높을수록 관련) |
| `rerank_rank` | 재정렬 후 순위(1부터) |

원래 하이브리드 순위(`rank`, `fusion_score`)와 나머지 필드는 **그대로 보존** — 리랭킹
전/후 비교(T2-4 Recall/MRR)에 필요하기 때문.

---

## 4. 의존성 (⚠️ 팀원 재현용)

`requirements.txt`에 아래를 넣어야 팀원 환경에서 같은 에러가 안 난다.

```
FlagEmbedding
transformers<5
```

- **transformers 버전 못 박기 필수.** 최신 transformers 5.x는 `XLMRobertaTokenizer`에서
  `prepare_for_model` 메서드가 제거돼, FlagEmbedding이 `AttributeError`로 죽는다.
  실제로 5.14.1에서 이 에러가 났고 → `transformers<5`(4.57.6)로 낮춰 해결.
- FlagEmbedding 설치 시 torch(CPU) 등 무거운 의존성이 함께 깔린다(설치에 수 분 소요).

## 5. 사용법

```
# 전체 실행 (출력 자동: hybrid_top20_reranked.jsonl)
venv/Scripts/python.exe src/candidate_reranker.py

# 소규모 테스트
venv/Scripts/python.exe src/candidate_reranker.py --limit 5
```

주요 옵션: `--input`, `--output`(미지정 시 _reranked 자동), `--model`,
`--query-field`(기본 claim_text), `--doc-field`(기본 tbl_name), `--limit`.

---

## 6. 성능 (CPU 노트북 기준)

- 모델 로드: 최초 다운로드 포함 ~2분, 이후 ~4초.
- 리랭킹: claim 3개(후보 60쌍) 약 37초 → claim당 ~12초. 전체 100개 ≈ **약 20분** 예상.
- PoC 실험용으로 충분(실시간 서비스 아님).

---

## 7. 검증 (테스트 3건)

리랭킹이 실제로 순서를 바꾸는지 확인됨. 예시:
```
주장: "나 홀로 사장님이 422만5000명으로 74.7%..."
  新1등 ← 原8등  "시도/직업/성/종사상의 지위별 취업자"   (관련 표를 끌어올림)
  新2등 ← 原5등  "성/산업/직업별 취업자"
```
- 후보 20개 유지, 원본 필드 보존, rerank_score/rerank_rank 추가 확인.

---

## 8. 전체 실행 결과 (100 claim)

- claim 100개 × 후보 20 = **후보쌍 2,000개 재정렬**, 소요 약 **21.5분** (CPU).
- 검증 통과: 각 claim 후보 20개 유지, `rerank_score`/`rerank_rank` 부여, 점수 내림차순 정렬.
- **리랭킹으로 1등 후보가 바뀐 claim: 84/100 (84%)** — 리랭커가 벡터DB 순서를 실제로
  재조정함(작동 확인). 단, 이 변화가 '정답 방향'인지는 골드셋 Recall/MRR로 확정해야 함.
- 산출물: `data/hybrid_top20_reranked.jsonl`.
