# 사람 판정 가이드 — R0 / R2 / R3

작성일: 2026-08-04

R0와 R2 판정은 완료됐다. 현재 남은 사람 판정은 R3 **256건**이다. 이 문서는 무엇을
먼저 하고, 각 화면에서 무엇을 묻는지, 언제 멈춰야 하는지만 적는다.

## 0. 진행 확인과 실행

어느 큐가 얼마나 남았는지:

```bash
venv\Scripts\python.exe -m src.develop.label status
```

판정 화면 실행 (브라우저가 자동으로 열린다):

```bash
venv\Scripts\python.exe -m src.develop.label open r0-dev
```

`r0-dev` 자리에 `r0-test` · `r2` · `r3`를 넣는다. 경로·포트·registry는 launcher가
들고 있으므로 외울 필요가 없다. 저장은 전부 자동이고 동결 시트는 건드리지 않는다
(`*_working.jsonl`에 쓴다). Ctrl+C로 언제든 멈췄다가 이어서 하면 된다.

## 1. 권장 순서

| 순서 | 큐 | 건수 | 한 건당 | 왜 이 순서인가 |
|---|---|---:|---|---|
| 완료 | `r2` | 225값 / 115문장 | — | 2026-08-05 완료, holdout-2 one-shot 측정까지 수행 |
| 1 | `r3` | 256 | 30초~2분 | 드래그 + 클릭. 가장 오래 걸리지만 R0처럼 외부 사이트를 오가지 않는다 |

`r0-test`와 `r2`(holdout-2)는 **동결 평가셋**이다. 판정 중에도 판정 뒤에도 모델
출력이나 Recall을 보고 되돌아가 고치지 않는다(CLAUDE.md 6.6절).

`status`와 `open`은 작업 파일의 행 ID·순서와 동결 입력 내용을 동결 시트와 대조한다.
R0 동결 시트 자체도 manifest SHA-256과 대조한다. 다르면 `!!`를
찍고 `open`은 **실행을 거부한다** — 시트가 다시 만들어진 뒤 이어서 판정하면 저장된
판단이 다른 표본에 속하게 되고, 그건 지표를 보고한 다음에야 드러난다.

## 2. R2 — 라우팅 (225건, 키 하나)

상태: **225/225 완료**. 아래 내용은 판정 계약을 재현할 때 참고한다.

묻는 것: **이 숫자가 KOSIS로 검증할 수치 주장인가.**

| 키 | 값 | 뜻 |
|---|---|---|
| `1` | `KOSIS_CANDIDATE` | 정부·공공기관이 정기 집계·공표하는 통계 수치 |
| `2` | `OUT_OF_SCOPE` | 수치 주장이지만 KOSIS 집계가 아님 (민간 조사, 전망·목표, 법정 기준, 개별 기업, 해외기관) |
| `3` | `NOT_CLAIM` | 애초에 통계 주장이 아닌 숫자 (날짜·나이·순번, 분모로만 쓰인 수) |

`←` `→` 이동, `Esc` 선택 해제. 진행률은 `문장 x/115 · 값 y/225`로 표시된다.
한 문장의 값들은 기본적으로 함께 판정된다
(`26.2%에서 18.6%로`는 한 판단을 두 번 쓴 것이다). 한 값만 다르면 그 값을 선택해
먼저 개별로 저장한 뒤, 선택을 푼 상태에서 나머지의 공통 class를 누른다. 먼저 저장한
예외값은 문장 판정에 덮이지 않는다.

판정 기준은 **기사가 옳은가가 아니라 KOSIS에 이런 통계가 있는가**이다. 수치가
틀렸어도 KOSIS로 대조할 수 있으면 `KOSIS_CANDIDATE`다.

## 3. R3 — L2 구조 (256문장)

묻는 것: **이 문장에서 어떤 지표가 어떤 값을 지배하는가, 수치의 출처는 무엇인가.**

원문을 드래그하면 span이 잡히고 값은 칩 클릭으로 연결한다. `scope_id`·offset·JSON은
전부 기계가 만든다. `보기 → 미검토만`으로 남은 것만 볼 수 있다.

- 확신 있는 `지배 없음`은 **빈칸이 아니라 `지배 없음`을 고른다.** 보류는 `판단 불가`다.
  (1차 라벨링에서 이 둘이 데이터에서 구별되지 않아 42행을 다시 봤다.)
- `앞에서 상속`은 "앞 문맥의 비슷한 주제"가 아니라 **앞에서 정의된 바로 그 지표**다.
- 저장 시점에 검증하므로 잘못된 라벨은 파일에 도달하지 않는다. 400이 뜨면 span이
  그 문장에 없거나 다른 문장의 값을 연결한 것이다.

## 4. R0 / G0-H — 검색 gold

묻는 것: **이 수치가 실제로 들어 있는 KOSIS 통계표는 무엇인가.**

이 화면은 어떤 검색기 후보도 보여주지 않는다. 표본과 정답을 검색기 출력에서 고르면
검색 성능 gold가 되지 못하기 때문이다(`R0` 재개방 사유).

초기 R0 dev 50/test 15는 완료됐다. `r0-dev2`는 기존 dev의 결과를 보고 행을
재선택한 표본이 아니라, 같은 147행 frame에서 최초 결정론적 순서의 **51~95번째
45행**을 미리 동결한 연장 배치다. 앞선 MATCH율은 배치 크기 산정에만 사용했고
행 선택에는 사용하지 않았다.

**화면의 `지표`·`기간`·`측정 유형`은 정답이 아니라 모델 L4 출력이다.** 지표 exact는
0.216이고, 이 표본에도 `1분기 성장률`이 `성장률`로 잘린 행이 들어 있다. 그 검색어로
못 찾았다고 `NO_KOSIS_MATCH`를 적으면 **검색 gold가 구조화 오류를 물려받는다** —
Gate B 해제가 켜려던 "검색 실패와 구조화 실패의 분리"가 무너진다. 그래서 이 필드들은
기본으로 접혀 있고, 편 행은 `model_fields_revealed`로 기록해 나중에 분리 보고한다.
열람 기록은 최종 판정을 저장할 때가 아니라 블록을 여는 즉시 영속화되며, 점프 목록에는
모델 지표 대신 원문 문장 앞부분만 표시된다.
**여는 것 자체는 잘못이 아니다.** 문장이 너무 짧아 판단이 안 서면 열되, 먼저 문장만
보고 자기 검색어를 만들어 보는 순서를 지킨다.

작업 흐름:

1. **문장만 보고** 이 수치가 어떤 통계인지 스스로 정한 뒤 `KOSIS 열기 ↗`에서 찾는다.
   어떤 검색어로 찾았는지는 메모에 남긴다. 막히면 `모델이 뽑은 구조화 필드 보기`를 편다.
2. KOSIS에서 표를 찾으면 **그 표 페이지의 주소를 그대로 붙여넣는다.** `orgId`·`tblId`만
   뽑아 `org_id:tbl_id`로 정규화된다. 손으로 옮겨 적지 않는 것이 요점이다 — 잘못
   옮긴 키가 레지스트리에 존재해 버리면 조용히 틀린 gold가 된다.
3. 입력 즉시 아래에 **표 이름과 분류 경로**가 뜬다. KOSIS에서 본 표와 같은지 확인한 뒤
   `Ctrl+Enter`로 저장한다. `✗`가 뜨면 저장되지 않는다.

| 키 | 상태 | 언제 |
|---|---|---|
| `1` | `MATCH` | 이 수치를 담은 표를 특정했다 |
| `2` | `NO_KOSIS_MATCH` | KOSIS에 이 수치의 표가 없다 |
| `3` | `AMBIGUOUS` | 표는 있는 것 같은데 어느 것인지 확정 못 하겠다 |

**못 찾았다고 그럴듯한 표를 고르지 않는다.** `NO_KOSIS_MATCH`와 `AMBIGUOUS`는 실패가
아니라 측정값이다. 직전 라운드에서 `표 없음` 20%는 구조화·검색이 완벽해도 남는
end-to-end 상한으로 보고됐고, 그것이 2.2절 `UNVERIFIABLE`을 정당화한다. MATCH 수를
늘리려고 애매한 표를 고르면 그 상한을 잃는다.

`AMBIGUOUS`는 대체로 "표는 맞는데 분류축이 다른" 경우이며 `Task 3-1` 셀 정렬로
넘어간다. 판단 근거를 메모에 남기면 그쪽에서 쓸 수 있다.

## 5. 판정 후

- `label status`가 네 큐 모두 완료를 보이면 각 Task의 완료 조건 검증을 돌린다.
- gold 확정 **전에는** 어떤 Recall도 성능 주장으로 쓰지 않는다(`R0` 7절, P0 원칙).
- `r0-test`·`r2` 결과를 본 뒤 같은 표본으로 코드를 교정하면 그 표본은 개발셋으로
  강등하고 오염을 기록한다(6.6절).
