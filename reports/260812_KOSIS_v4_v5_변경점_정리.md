# KOSIS 파이프라인 v4 → v5 변경점 정리

작성일: 2026-08-12
목적: v4(기존)에서 v5(크롤링_v5)로 무엇이·왜 바뀌었는지를 파이프라인 단계별로 한자리에 모은다.
      상세 근거는 각 단계 문서에 있고, 이 문서는 "차이"만 압축한다.

관련 문서: 계획서 `260810_..._계획서.md` · 실행순서 `260810_..._실행순서.md` ·
          결과보고서 `260811_..._결과보고서.md` · 정기업데이트 `KOSIS_v5_정기업데이트_가이드.md`

## 0. 한 줄 요약

**v4 = 서비스뷰 1개(주제별) · 단발 크롤 · 검색만.**
**v5 = 서비스뷰 11개 전수 · 정기 갱신(승계) · 검색+필터+검증 연결.**

| 지표 | v4 | v5 |
|---|---|---|
| 수집 뷰 | MT_ZTITLE 1개 | **11개** (기관·국제·북한·작성중지·광복이전 등) |
| 유니크 표 | 265,094 | **287,671** (+22,577) |
| 폴더 | `src/*.py`, `data/*` (혼재) | `src/크롤링_v5/`, `data/크롤링_v5/` (격리) |
| 정기 갱신 | 없음 (매번 전량) | **승계** — 안 바뀐 표는 재수집 안 함 (66h→수h) |
| 삭제 표 | 개념 없음 | **retired 마킹** (삭제 안 함, 이력 보존) |

---

## 1. 수집 범위 — 뷰 1개 → 11개

v4는 `MT_ZTITLE`(국내통계 주제별) 하나만 긁었다. KOSIS는 같은 통계를 여러 "서비스뷰"로
진열하는데, 뷰마다 담긴 표가 다르다. v5는 개발가이드 게재 11개를 전수 크롤했다.

**v5가 새로 확보한 것 (뷰별 신규):**

| 뷰 | 표 수 | v4엔 왜 없었나 |
|---|---|---|
| MT_STOP_TITLE (작성중지) | 14,944 | 뷰 자체를 안 긁음 |
| MT_CHOSUN_TITLE (광복이전) | 2,314 | 〃 |
| MT_RTITLE (국제) | 2,294 | 〃 |
| MT_HANKUK_TITLE (통계연감) | 1,097 | 〃 |
| MT_BUKHAN (북한) | 997 | 〃 |
| 기타 (TM1·TM2·GTITLE01) | ~1,475 | 〃 |

→ 뉴스에서 "북한 인구", "일제강점기 통계", "작성중지된 옛 통계" 주장을 검증하려면
  이 표들이 필요한데, v4엔 통째로 없었다.

**제외된 것:**
- `MT_GTITLE02` (e-지방지표 지역별): 243개 지역이 tbl_id 2개를 공유해 병합 시 뭉개짐 → 보류
- `MT_ETITLE` (영문): 미러
- 분류 밖 표 2건(환율·외환보유액): KOSIS 공식 "사용 말라" 답변 → `보류/`에 별도 보관

## 2. 수집 필드 — 4개 더 받음 (트리 크롤 단계)

`statisticsList.do` 응답이 8필드인데 v4는 4개만 저장했다. v5는 전부 받는다.

| 필드 | v4 | v5 | 용도 |
|---|---|---|---|
| org_id·tbl_id·tbl_nm·stat_id | ✅ | ✅ | 기존 |
| **send_de** (최종갱신일) | ❌ | ✅ | 정기 갱신 승계 판정의 핵심 |
| **rec_tbl_se** (추천표) | ❌ | ✅ | 리랭킹 가산점 |
| **vw_cd** (소속 뷰) | ❌ | ✅ | 뷰 필터 |
| **path_ids** (경로 ID) | ❌ | ✅ | 분류 개편돼도 표 추적 |

`send_de`가 특히 중요하다 — 이게 있어야 "이 표가 언제 마지막 갱신됐나"를 알아 정기
업데이트 때 안 바뀐 표를 건너뛴다. v4엔 없어서 매번 전량 재수집이 불가피했다.

## 3. 크롤러 결함 수정

| 결함 | v4 | v5 |
|---|---|---|
| err 응답을 "표 없음"으로 오해 | 서브트리 통째 유실 (조용히) | err 30만 흡수, 나머지 예외 |
| 실패 노드 기록 | 없음 (WARN 한 줄) | `kosis_crawl_failures_v5.jsonl`에 영구 기록 |
| 재시도 | 없음 | 4회 + err40 쿨다운 |
| 중단·재개 | 대분류 단위 | 노드 단위 체크포인트 (200콜마다) |
| 조용한 유실 감시 | 없음 | audit (skipped/empty/unknown 계수) |

## 4. 병합 — 신규 단계 (v4엔 없음)

v4는 뷰가 1개라 병합이 필요 없었다. v5는 11개 뷰를 `org_id:tbl_id`로 접는다.

- 같은 표가 여러 뷰에 = 표 1건 + 뷰별 `category_paths`
- `status: active/retired` 부여
- 직전 판과 대조해 사라진 표 retired 마킹
- 산출물: `kosis_table_tree_master_v5.jsonl` (287,671건)

---

## 5. 메타 보강 — 승계 추가

| | v4 | v5 |
|---|---|---|
| 입력 | 트리 | 마스터 |
| 승계 | 없음 (전량 getMeta) | **send_de 비교로 안 바뀐 표 승계** |
| 비용 | 66시간 | **6.3시간** (승계 90.6%) |
| 병렬화 | 8워커 | 8워커 (동일, 검증됨) |
| 출력 | 덮어씀 | **날짜 스냅샷** (`_YYMMDD`) |

승계 판정:
- 첫 판(v4→v5): v4에 send_de 없어 fetched_at 근사
- 2판 이후: send_de 정밀 비교 (경계 문제 없음)

## 6. 카탈로그 — 필드 6개 추가 + 버그 수정

3층 구조(doc_meta_text 임베딩 / doc_item_index BM25 / payload)는 계승. 달라진 점:

**신규 필드 (+6):**

| 필드 | 용도 |
|---|---|
| view_codes | 뷰 필터 |
| status | **retired 제외** (검색에 은퇴표 안 나오게) |
| send_de | 최신성 필터 |
| rec_tbl_se | 리랭킹 가산점 |
| primary_view / primary_path | 임베딩용 대표 경로 |

**제거 (-1):** source → manifest로 (26만 번 중복이라)

**값 개선:**
- `items[].unit_nm` (항목별 단위) 보존 — v4는 버렸음
- `latest_period` 재계산 — v4는 `max(문자열)`이라 "2026.06"(월) vs "2025"(연) 혼재 시 부정확
- `category_paths` 뷰별 dict + ID 보존 — v4는 뷰 없는 평면 리스트
- HTML 태그 제거 (부등호는 보존)

**대표 경로 처리 (신규 개념):** — 상세는 §6.5
- 겹치는 표는 뷰마다 경로 맥락이 다르다(실측 100%). 예: "대학교 학생수" = 교육(GTITLE01) vs 학생(TM1)
- `doc_meta_text` 엔 대표 경로 1개(MT_ZTITLE 우선, 99.99% 자동)만 넣는다
- 대표 아닌 나머지 경로는 **검색 텍스트(doc_meta_text·doc_item_index)에 넣지 않고** `category_paths`(payload)에만 원본 보존한다 (v4 동작으로 복귀, 2026-08-12 결정)
- `doc_item_index` 는 v4와 동일하게 항목명 + 차원값 이름만 담는다

**차원값 코드는 카탈로그에 안 넣음 (A방식):**
- 검색은 이름(doc_item_index), 검증은 코드(get_data)
- 코드는 메타 파일에 살아있어 검증 시 메타 참조 (실측: 종로구 → 메타 id "11110" → get_data → 72274)
- 카탈로그를 무겁게 안 하려고 중복 저장 안 함

## 6.5 경로(category path)가 카탈로그에 저장되는 방식 — v4 vs v5

경로 처리가 v4 → v5에서 가장 크게 바뀐 부분이라 따로 정리한다. **어떻게 색인할지는
색인기 담당이 정한다. 이 절은 "데이터가 어떤 모습으로 저장돼 있는지"만 기술한다.**

### v4 — 경로 하나의 리스트 (뷰 개념 없음)

```json
"category_paths": [["범죄·안전", "경찰접수교통사고현황"]]
```
- 뷰가 MT_ZTITLE 하나뿐이라 경로도 평면 리스트
- 이름만 있고 ID 없음
- doc_meta_text 에는 이 경로들을 ` ; ` 로 다 이어붙였다

### v5 — 뷰별 dict + ID + 대표 경로 분리

같은 표라도 뷰마다 경로가 다르다(v5는 11개 뷰). 그래서 세 필드로 나눠 저장한다.

표: `분단 이후 출생인구` (뷰 2개) 실물:

```json
"category_paths": {
  "MT_BUKHAN":   [{"names": ["주제별","영토/인구"],      "ids": ["101_001","101_001_001"]}],
  "MT_TM2_TITLE":[{"names": ["출생·사망","출생 및 출산율"], "ids": ["101_B05","101_B0501"]}]
},
"primary_view": "MT_BUKHAN",
"primary_path": ["주제별", "영토/인구"],

"doc_meta_text":  "분단 이후 출생인구 | 주제별 > 영토/인구 | 남북한별",
"doc_item_index": "인구 인구비율 북한 남한 남북한"
```

> 위 예에서 대표 아닌 경로(MT_TM2_TITLE의 `출생·사망`, `출생 및 출산율`)는 검색 텍스트에
> 넣지 않는다. 그 경로는 `category_paths` 에만 원본으로 남는다.

| 필드 | v4 | v5 | 담긴 내용 |
|---|---|---|---|
| `category_paths` | 평면 리스트 `[[...]]` | **뷰별 dict** `{뷰:[{names,ids}]}` | 전체 경로 원본 (뷰 구분 + ID) |
| `primary_view` | 없음 | **신규** | 대표로 고른 뷰 코드 |
| `primary_path` | 없음 | **신규** | 대표 경로 하나 (MT_ZTITLE 우선) |
| `doc_meta_text` | 모든 경로 ` ; ` 연결 | **대표 경로 하나만** | 표명 + primary_path + 차원명 |
| `doc_item_index` | 항목·차원값 | **항목·차원값** (v4와 동일) | 대표 아닌 경로는 넣지 않음 |

### 무엇이 달라졌나 (요점)

1. **경로에 ID가 생겼다** (`ids`) — v4는 이름만. 분류가 개편돼도 ID로 표 추적 가능.
2. **뷰 출처를 보존한다** — v4는 경로가 어느 뷰에서 왔는지 몰랐다. v5는 뷰별로 나뉜다.
3. **대표 경로를 명시한다** (`primary_path`) — v4는 모든 경로를 doc_meta_text 에 이어붙여
   길어졌다(다중 뷰면 벡터가 흐려짐). v5는 대표 하나만 doc_meta_text 에 넣는다.
4. **대표 아닌 경로는 검색 텍스트에서 뺀다** — doc_meta_text·doc_item_index 어디에도
   넣지 않고 `category_paths`(payload)에만 원본 보존한다(v4 동작으로 복귀, 2026-08-12 결정).
   검색 텍스트는 대표 경로 하나로 유지하되, 원본 경로는 payload 에 그대로 남는다.

## 7. 산출물 비교 (실측 2026-08-12)

| 산출물 | v4 | v5 | 비고 |
|---|---|---|---|
| 트리/마스터 | `kosis_table_tree.json` 100MB · 리프 3,475,963 | `kosis_table_tree_master_v5.jsonl` 210MB · **표 287,671** | v4는 리프(경로중복 포함), v5는 표 단위 유니크 |
| 메타 | `kosis_table_meta_v4.jsonl` 1,419MB · 265,094 | `kosis_table_meta_v5_YYMMDD.jsonl` 1,528MB · **287,671** | send_de 심음 |
| 카탈로그 | `kosis_catalog_v4.jsonl` 534MB · 265,094 | `kosis_catalog_v5_YYMMDD.jsonl` 735MB · **287,671** | 필드 6개↑ |
| 기관명 | `kosis_org_names.json` 183개 | `kosis_org_names_v5.json` **1,558개** | 전수 수집 |

> 트리는 형태가 다르다 — v4는 한 파일 안에 대분류별 리프 목록(경로 중복 포함 347만 줄),
> v5는 뷰 병합 후 표 단위 유니크(287,671줄). 그래서 "건수"를 직접 비교하면 안 되고,
> v5의 287,671이 실제 유니크 표 수다.

> 기관명이 183 → 1,558로 는 것은 v5가 `getMeta type=ORG`로 등장 기관을 전수 수집했기 때문.
> (검색 티커 조사분·구·군 단위 포함)

색인(벡터DB) 단계는 이 문서 범위 밖 — 카탈로그까지가 v5 크롤링 파이프라인의 산출물이다.

## 8. 폴더·명명 정리

| | v4 | v5 |
|---|---|---|
| 스크립트 | `src/*.py` (기존과 혼재) | `src/크롤링_v5/` |
| 산출물 | `data/*` | `data/크롤링_v5/` |
| 마스터 | (없음) | `kosis_table_tree_master_v5.jsonl` |
| 메타 | `kosis_table_meta_v4.jsonl` (덮어씀) | `kosis_table_meta_v5_YYMMDD.jsonl` (판별 보존) |
| 카탈로그 | `kosis_catalog_v4.jsonl` | `kosis_catalog_v5_YYMMDD.jsonl` |

기존 v4 파일(`src/*.py`, `data/kosis_*`)은 **손대지 않음** — v5는 별도 폴더에서 완결.

