### 1차 프로젝트 한계점
1. 기존 “JSON 성공률”은 JSON 객체로 파싱됐는지만 확인하고, 필수 필드·타입·배열 구조를 만족했는지 검증하지 못함
2. claim_class 허용값을 프롬프트에서 고정하지 않아 모델이 ‘집계통계’ 대신 economic, 금융 같은 임의의 주제명을 출력
3. 단위 정확도는 전체 단위 문자열 완전일치 방식이라 구조화 품질을 적절히 반영하지 못함
4. indicator_raw, population Label 부재
5. KOSIS gold_tbl_id 컬럼 부재
6. 다중 수치 평가에 필요한 사례가 총 3건뿐

| 평가 항목 | 현재 가능 여부 | 문제 |
|---|---|---|
| is_claim | 가능 | silver label 기반 |
| 주장 유형 | 형식상 가능 | 프롬프트 enum 미정의 |
| 스키마 성공률 | 재계산 가능 | 현재는 단순 JSON 파싱률 |
| 수치·단위·시점 | 일부 가능 | 규칙 추출값이지 사람 검수 gold가 아님 |
| 지표·모집단 | 불가능 | gold 컬럼 없음 |
| 다중 수치 분해 | 사실상 불가능 | 평가 사례 3건 |
| KOSIS 매핑 | 불가능 | gold table ID 0건 |

실험을 다시 설계해야 함

---
#### 1. 스키마 출력 성공률
단순 JSON 파싱률을 버리고 JSON Schema 검증률을 사용해야 함
- JSON 파싱 성공률
- 필수 필드 완전성
- 필드 타입 일치율
- `observations` 배열 구조 유효율
- 전체 Schema valid Rate

`is_claim = False` 일 때도 사전에 정의한 최소 출력 계약을 만족하는지 확인해야 함
---

#### 2. 주장 유형 분류
프롬프트에 허용 클래스를 명시한 후 다시 실행해야 함
- Macro-F1: 희소 클래스까지 동일 비중으로 평가
- Weighted-F1: 전체 운영 성능 확인
- 클래스별 Recall
- Confusion Matrix

현재처럼 `집계통계`가 85/120건인 불균형 데이터에서는 Accuracy보다 **Macro-F1과 집계통계 Recall이 중요**
---

#### 3. 필드 추출 정확도
필드별 평가 방식을 분리해야 함

| 필드 | 권장 평가 |
|---|---|
| 지표·모집단 | 정규화 Exact Match + Token F1 |
| 수치 | 숫자 정규화 후 Exact Match |
| 단위 | 단위 표준화 후 Exact Match |
| 시점 | 원문 표현 Exact + 정규화 시점 Exact |
| 전체 구조 | 필수 필드 모두 맞는 Claim Exact Match |
---

#### 4. 다중 수치 분해
전용 평가셋 필요
- Observation 개수 정확도
- (value, unit, period) 튜플 Precision / Recall / F1
- 수치와 시점 연결 정확도
- 순서 정확도
- `relation_type` Macro-F1

+ 현재 3건으로는 모델 간 차이를 평가하기 어려움. 최소 30~50개의 다중 수치 문장을 별도로 확보해야 함
---

#### 5. KOSIS 통계표 매핑
- Recall@K
- MRR
- 올바른 `TBL_ID` 선택률
- 올바른 표 / 항목 / 분류코드 / 시점까지 모두 맞춘 End-to-End Accuracy
- KOSIS 범위 밖 주장에 대한 불필요한 검색 억제율
---

#### 최종 구조화 모델 선택 시 사용할 만한 지표

Q = 
Schema Valid Rate $\times$ Claim Class Macro-F1 $\times$ Observation Tuple F1 $\times$ Mapping Recall@K


그다음 기존 RLT 구조 확장


구조화 효율 점수 = $Q^{0.6}\times LatencyEfficiency^{0.2} \times TokenEfficiency^{0.2}$

**구조화/매핑용 확장 지표**로만 사용. 메인 지표 X

### Labeling 전략


#### (1) 규칙 기반으로 1차 후보군 생성
```
전체 기사 2,706건 → 규칙 기반 후보 탐지 → 1차 후보 문장 약 7,043개
```

#### (2) 평가할 층화 표본만 추출
모델 비교에 사용할 표본만 추출. 약 500건 <br>
층화 기준:
- 단일 수치 / 다중 수치
- 비교 표현 유무
- 출처 명시 / 미명시
- KOSIS 키워드 포함 / 미포함
- `ALIGNED`, `COUNT_MISMATCH`, `LOW_CONFIDENCE` 등 추출 상태
- 기사 중복 방지
- 다양한 주장 유형

#### (3) 표본에 silver label을 미리 생성
사람이 모든 필드를 입력하지 않도록 규칙 or LLM이 초안을 생성
```
표본 300개 → 규칙/LLM으로 필드 사전 입력 → silver label 생성
```

자동으로 미리 채울 항목:
- `is_claim`
- `claim_class`
- `source_scope`
- `indicator_raw`
- `population`
- 수치/단위/시점
- observation 목록

#### (4) 사람이 표본만 검수해 gold set 생성
사람은 표본 500개만 검수.

**필수 검수 항목**
- `is_claim`
- `claim_class`
- `source_scope`
- `indicator_raw`
- 수치
- 단위
- 시점
- 다중 수치 분리 결과

**코드가 자동으로 처리할 항목**
- 숫자 정규화
- 단위 표준화
- ID 생성
- 스키마 유효성
- 필드 개수
- 날짜 형식 변환

→ 사람은 초안을 보고 맞으면 승인, 틀린 부분만 수정

#### (5) 동일 조건으로 HCX 모델 비교
사람 검수 gold 기준 모델만 변경해서 실험 <br>
고정 조건:
- 동일 입력 300건
- 동일 프롬프트
- 동일 temperature
- 동일 top-p
- 동일 최대 토큰
- 동일 출력 스키마

평가 지표:
| 지표 | 평가 목적 |
|---|---|
| Claim Recall | 검증할 주장을 놓치지 않는지 |
| Precision·F1 | 불필요한 후보와 누락의 균형 |
| JSON 성공률 | 후속 자동 처리가 가능한지 |
| Claim Class Macro-F1 | 희소 주장 유형도 구분하는지 |
| 지표·수치·단위·시점 Exact/F1 | 구조화가 정확한지 |
| 평균 지연시간 | 전체 처리시간 |
| 평균 토큰 | 비용·처리 효율 |
| RLT | Recall·속도·토큰의 종합 효율 |

#### (6) 최종 구조화 모델 선정
평가 결과를 바탕으로 모델 선정
```
구조화 정확도 + JSON 출력 안정성 + 처리 속도 + 토큰 효율 + RLT
```

#### (7) 선정 모델로 전체 후보군 자동 구조화
선정한 모델을 1차 후보군 전체(claim_listform.csv)에 적용

#### (8) 실패/저신뢰 결과만 추가 검수
전체 자동 처리 결과에서 문제가 의심되는 행만 골라냄

추가 검수 대상:
- JSON 파싱 실패
- 필수 필드 누락
- 수치 개수 불일치
- 단위 누락
- 다중 수치 분해 실패
- 모델과 규칙 결과 불일치
- source_scope가 불명확한 사례
- KOSIS 검증 가능 여부가 애매한 사례

→ 문제 행만 사람 검수

#### (9) KOSIS 매핑 평가용 표본을 별도로 구성
구조화가 끝나면 `집계통계 + KOSIS 범위`로 분류된 주장 중 100~200건 추출
```
전체 구조화 결과 → KOSIS 검증 가능 주장 선별 → 매핑 평가 표본 100~200건 추출
```

여기서도 다양한 주제 포함
- 고용
- 인구
- 물가
- 무역
- 주거
- 농림수산
- 기업·산업

#### (10) 이 표본만 사람이 실제 통계표까지 확인
KOSIS 매핑 표본에 대해서만 사람이 다음을 확인
- KOSIS 매핑 가능 여부
- 올바른 통계표 `TBL_ID`
- 올바른 지표 항목
- 모집단/지역/성별 등 분류 조건
- 조회 시점
- 단위
- 뉴스 수치와 비교 가능한지

#### (11) 통계표 매핑 방법 평가
사람이 확인한 KOSIS gold set을 기준으로 검색/재정렬 성능 평가

지표:
- Recall@K (K는 선정할 후보 개수)
- MRR
- Top-1 Accuracy
- 올바른 `TBL_ID` 선택률
- 올바른 시점/분류 조건 선택률
- 조회 성공률
- 판단불가 구분 정확도
