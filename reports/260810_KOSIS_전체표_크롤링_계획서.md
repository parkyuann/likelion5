## 1. 분류 밖에 존재하는 표를 확인했다

### 1.1 발견 경위

KOSIS 국가통계포털에서 "환율"을 검색하면 상단 지표 티커에 `원/미국달러 환율(매매가기준)`이 뜬다. 그 링크를 파싱하면:

```
generator_htmlLink('301','DT_731Y001','','','','','','','0341054452','전국')
```

→ `ORG_ID=301`(한국은행), `TBL_ID=DT_731Y001` = **「주요국 통화의 대원화환율」**

### 1.2 다섯 방향 검증

| 확인 | 방법 | 결과 |
|---|---|---|
| 표가 실재하는가 | `getMeta type=TBL` | ✅ `주요국 통화의 대원화환율` / `Arbitraged Rates of Major Currencies Against Won` |
| 현재 트리에 있는가 | `kosis_table_tree.json` 265,094건 검색 | ❌ `DT_731Y001`·`대원화` 0건 |
| **기관별 뷰에 있는가** | `MT_OTITLE` 한국은행(301) 서브트리 **전수 BFS** (134콜 완주, 리프 **349건**) | ❌ 없음. `DT_731Y*` 계열 0건 |
| 검색 API로 잡히는가 | `statisticsSearch.do` — `환율`·`주요국` 각 100건, `대원화환율`·`Arbitraged` | ❌ 전부 미포함 |
| 갱신일 대장에 있는가 | `getMeta type=NCD` | ❌ `err 30 데이터가 존재하지 않습니다` |

**결론: "우리가 안 긁은 뷰에 있는 표"가 아니라, 분류 트리·검색 인덱스·갱신일 대장 어디에도 없는 표다.** `getMeta type=TBL`과 `getData`는 정상 동작하므로 데이터 자체는 실재한다.

세 번째 항목이 결정적이다. 선행 계획서가 "미수집 뷰"로 지목한 `MT_OTITLE`을 실제로 전수 크롤했는데, 한국은행 349건은 현재 트리의 `org_id=301` 건수(349건)와 **정확히 일치**했고 그 안에도 없었다.

> 이름이 비슷한 `301:DT_036Y001_REC`(주요국통화의 대원화 환율, 외환수급통계)는 `MT_STOP_TITLE`에 있고 검색에도 잡히는 **별개 표**다. 혼동 주의.

### 1.3 단발 예외가 아니다 — 공식 총량과의 갭

공유서비스 첫 화면(`kosis.kr/openapi/index/index.jsp`)이 공식 수치를 게시하고 있다:

```
통계목록 13 건 · 통계자료(통계표) 289,906 건 · 통계설명자료(조사) 1,523 건 · 통계주요지표 1,473 건
```

| 항목 | 건수 |
|---|---|
| **공식 「통계자료(통계표)」** | **289,906** |
| 현재 수집분 (`MT_ZTITLE`) | 265,094 |
| + 확정 미수집 뷰 신규(최소, §2) | +8,825 |
| 뷰 전수 예상 합계 | 273,919 |
| **미설명 차이** | **약 15,987** |

**뷰 개수는 "뷰 기반 수집의 상한"이지 KOSIS 전체가 아니다.** 뷰를 12개로 하든 13개로 하든 17개로 하든 이 갭은 그대로 남는다.

### 1.4 갭 조사 단서

**통계주요지표 서비스**가 별도로 존재한다.

- 엔드포인트: `https://kosis.kr/openapi/pkNumberService.do?method=getList&service=1&serviceDetail=pkNotion`
- 파라미터: `jipyoId`(지표ID) 필수
- 출력: `statJipyoId`, `statJipyoNm`, `jipyoExplan1`(개념), `jipyoExplan2`(선정방법), `jipyoExplan3`(출처정보)
- **지표 코드표는 `https://kosis.kr/openapi/openApiCodeList.do`에서 XLS로 API 키 없이 내려받힌다** (1,473건, 시트 2개: `지표명 및 지표ID 코드표` / `목록ID 코드표`)

한계: 코드표에 `orgId`/`tblId` 컬럼이 **없다.** 지표→표 매핑은 웹 링크의 `generator_htmlLink(orgId, tblId, ...)` 파싱이 필요하다. 이것이 P10의 출발점이다.

## 2. 수집 대상 뷰 — 13개로 확정

### 2.1 개발가이드는 12개, 웹은 13개, 집합이 어긋난다

**① 공유서비스 개발가이드**(`openapi/devGuide/devGuide_0101List.do`)의 `vwCd` 요청변수 설명 — **12개**:

```
MT_ZTITLE(국내통계 주제별)      MT_OTITLE(국내통계 기관별)
MT_GTITLE01(e-지방지표 주제별)  MT_GTITLE02(e-지방지표 지역별)
MT_CHOSUN_TITLE(광복이전 1908~1943)  MT_HANKUK_TITLE(대한민국통계연감)
MT_STOP_TITLE(작성중지통계)     MT_RTITLE(국제통계)
MT_BUKHAN(북한통계)             MT_TM1_TITLE(대상별통계)
MT_TM2_TITLE(이슈별통계)        MT_ETITLE(영문 KOSIS)
```

**② 웹 DOM/JS 전수 스캔** — kosis.kr 페이지 8개 + 로드 스크립트 21개에서 `MT_[A-Z0-9_]+` 추출 → 유효 뷰 **13개**.

**대칭차**:

| | 웹 메뉴 | 개발가이드 |
|---|---|---|
| 공통 11개 (ZTITLE·OTITLE·GTITLE01·GTITLE02·CHOSUN·HANKUK·STOP·RTITLE·BUKHAN·TM1·TM2) | ✅ | ✅ |
| `MT_GTITLE03` (e-지방지표 테마별) | ✅ | ❌ **누락** |
| `MT_RTITLE01` (국제지역통계) | ✅ | ❌ **누락** |
| `MT_ETITLE` (영문 미러) | ❌ | ✅ |

> 참고: 웹 스캔에서 `MT_ATITLE`도 문자열로 잡히지만 이것은 **뷰 코드가 아니라 통합검색 응답의 출력 필드명**(`KOSIS 통계표 위치`)이다. `devGuide_0701List.do`에서 확인.

### 2.2 왜 개발가이드 12개만 쓰면 안 되나

`MT_GTITLE03`·`MT_RTITLE01`은 KOSIS 웹 좌측 메뉴에 **정상 노출되는 서비스**이고, 선행 계획서 실측으로 **ZTITLE 대비 100% 신규**다:

| vwCd | 표본 수집 | 신규 |
|---|---|---|
| `MT_RTITLE01` | 545 (완주) | **545 (100%)** |
| `MT_GTITLE03` | 104 (완주) | **104 (100%)** |

문서만 믿으면 **최소 649건이 그냥 사라진다.** 의도적 제외가 아니라 **문서 갱신 누락**으로 판단한다. → **문서를 상한이 아니라 하한으로 취급한다.**

### 2.3 확정 범위

| 구분 | vwCd | 판단 |
|---|---|---|
| **수집 (13개)** | ZTITLE · OTITLE · STOP_TITLE · CHOSUN_TITLE · HANKUK_TITLE · RTITLE · RTITLE01 · BUKHAN · GTITLE01 · GTITLE02 · GTITLE03 · TM1_TITLE · TM2_TITLE | 웹 메뉴 노출분 전부 |
| **제외** | `MT_ETITLE` | 영문 미러 |
| **보류 → P2'에서 판정** | `MT_PTITLE` · `MT_ATITLE01` · `MT_ATITLE02` | 웹·JS·문서 어디에도 없는 순수 API 전용, 구 분류·큐레이션 뷰 |

보류 3개에 대한 주의: 선행 계획서가 잰 "신규 322건"(PTITLE 61 · ATITLE01 213 · ATITLE02 48)은 **`MT_ZTITLE` 하나와만 비교한 값**이다. 13개 뷰 합집합과 대조하면 0일 수 있다. **P2'에서 합집합 대조 후 판정**하고, 신규가 0이면 영구 제외를 확정한다.

**확정 미수집 최소치 = 8,825건** (2,314+2,294+1,215+1,097+997+545+257+104+2). 선행 계획서의 9,179건에서 보류 3개 뷰 + TM1/TM2 분(354건)을 뺀 값이다. 작성중지통계·`MT_OTITLE`은 미측정이므로 실제 총계는 이보다 커진다.

## 3. 수집 필드 — API가 8개 주는데 4개만 받고 있다

### 3.1 `statisticsList.do` 실측 응답

통계표 행의 실제 키 (`MT_ZTITLE` / `S1_301006_002` 호출):

```
['STAT_ID', 'SEND_DE', 'TBL_ID', 'REC_TBL_SE', 'ORG_ID', 'VW_NM', 'TBL_NM', 'VW_CD']

DT_641Y001  SEND_DE='2026-08-09'  REC_TBL_SE='N'  한국은행 원화대출금
DT_103Y002  SEND_DE='2026-08-09'  REC_TBL_SE='N'  한국은행 주요계정(말잔)
```

| API 필드 | 설명 | 현재 트리 | v5 |
|---|---|---|---|
| `ORG_ID` | 기관코드 | ✅ `org_id` | ✅ |
| `TBL_ID` | 통계표ID | ✅ `tbl_id` | ✅ |
| `TBL_NM` | 통계표명 | ✅ `tbl_nm` | ✅ |
| `STAT_ID` | 통계조사ID | ✅ `stat_id` | ✅ |
| **`SEND_DE`** | 최종갱신일 | ❌ **버림** | ✅ 신규 |
| **`REC_TBL_SE`** | 추천 통계표 여부 | ❌ **버림** | ✅ 신규 |
| **`VW_CD`** | 서비스뷰ID | ❌ **버림** | ✅ 신규(검증용) |
| **`VW_NM`** | 서비스뷰명 | ❌ **버림** | ✅ 파일 헤더에만 |
| **`LIST_ID`** | 목록ID (중간 노드 행) | ❌ 큐에만 쓰고 버림 | ✅ 신규 `path_ids` |
| `LIST_NM` | 목록명 (중간 노드 행) | △ `path`로 조립 | ✅ 유지 |

개발가이드는 필드 10개를 명시하지만, **통계표 행에는 `LIST_ID`/`LIST_NM`이 실리지 않는다** — 그 둘은 중간 목록 행에 온다.

`path`는 API 필드가 아니라 `kosis_tree_crawler.py:134`가 `LIST_NM`을 누적해 만든 값이며, `LIST_ID`는 큐에만 쓰고 버려진다. 그래서 현재 트리의 경로는 **이름만 있고 ID가 없다**.

### 3.2 `SEND_DE` — 통계목록 것과 `getMeta NCD` 것은 다른 물건이다

문서상 이름부터 다르다(최종갱신일 vs 자료갱신일). 실측 비교:

| | `statisticsList.do` | `getMeta type=NCD` |
|---|---|---|
| **행 단위** | **표당 1행** | **(수록주기 × 수록시점)당 1행** |
| 실측 | `2026-08-09` | `301/DT_103Y002` → **967행** (전부 `2026-08-09`) |
| 함께 오는 필드 | 표 목록 전체 | `ORG_NM`, `TBL_NM`, `PRD_SE`, `PRD_DE` |
| 호출 단위 | 노드 1회 ≈ 표 10건 | 표 1건 |
| ZTITLE 전수 비용 | **~26,509콜 (~2.5h)** | ~265,094콜 (~24.5h) |

**드리프트 판정에는 통계목록 `SEND_DE`를 쓴다.** NCD는 "어느 시점 자료가 언제 개정됐나"를 보는 용도로 성격이 다르고 10배 비싸다.

**문서 오류 2건 확인**:
- 개발가이드는 `SEND_DE`를 `VARCHAR2(8)`로 적었으나 실제는 `YYYY-MM-DD` **10자**다. NCD 쪽 `VARCHAR2(20)`도 실제로는 같은 10자 형식이다.
- NCD 요청변수 표에 **`tblId`가 빠져 있다.** `orgId`만 보내면 `err 20 필수요청변수값이 누락되었습니다`. 필수 파라미터다.

### 3.3 `REC_TBL_SE` — KOSIS 검색결과의 「추천」 배지

검색 페이지 렌더링 코드에서 정체를 확인했다:

```js
if(resultList[i].REC_TBL_SE == 'Y'){ html += "<span class='IconHit'>추천</span>"; }
if(resultList[i].recmTblYn   == 'Y'){ html += "<span class='IconHit'>인기</span>"; }
```

값은 `Y`/`N`. KOSIS에서 검색했을 때 표 이름 옆에 붙는 **「추천」 딱지**를 결정하는 값이다 — KOSIS가 "이 주제를 찾는 사람은 보통 이 표를 봐야 한다"고 지정해둔 대표표 표시.

> **「인기」 배지는 다른 필드(`recmTblYn`)이며 OpenAPI로 제공되지 않는다.** 조회수 기반으로 추정되고 웹 전용이다. 혼동하지 말 것.

표본 267건(4개 대분류, 대분류당 호출 25회 상한) 실측 분포:

| 대분류 | 표본 | `Y` | 비율 |
|---|---|---|---|
| P2 물가 | 51 | 2 | 3.9% |
| D 노동 | 59 | 4 | 6.8% |
| A 인구 | 114 | 5 | 4.4% |
| S1 금융 | 43 | 0 | 0.0% |
| **합계** | **267** | **11** | **4.12%** |

`Y`로 뽑힌 표들:

```
101 DT_1B8000F      인구동태건수 및 동태율 추이(출생,사망,혼인,이혼)
101 DT_1B26001_A01  시군구별 이동자수
101 DT_1B28025      내외국인/성/연령별 국제이동(월간, 연간)
101 DT_1J52         농가판매가격지수(2010=100,분기)
118 DT_11830_N001   의무고용사업체 장애인고용 현황
```

**뉴스가 실제로 인용하는 대표표들이다.** `candidate_reranker.py`가 점수로 근사하려던 "이 표가 이 주제의 대표표인가"를 KOSIS가 사람 손으로 매겨둔 값이므로, 랭킹 가산점 피처로 유효하다.

주의 두 가지:
- **4.12%는 과대추정일 수 있다.** 호출 상한을 건 BFS 표본이라 트리 상단에 치우쳐 있다. 추천표가 상단에 몰려 있을 테니 전수로는 더 낮게 나올 것이다. 정확한 값은 P6 이후 집계한다.
- **하드 필터로 쓰면 안 된다.** `S1 금융`은 표본 `Y`가 0건인데 환율·금리는 뉴스 단골 주제다. `Y`만 후보로 삼으면 금융 주장은 검증 자체가 불가능해진다. **후보 생성은 전체를 보고, 랭킹에서만 가산한다.**

### 3.4 `getMeta type=ORG` — 기관명 380콜 해법

```
301 → {"ORG_NM":"한국은행",     "ORG_NM_ENG":"Bank of Korea"}
101 → {"ORG_NM":"국가데이터처", "ORG_NM_ENG":"Ministry of Data and Statistics"}
999 → {"ORG_NM":"조선총독부통계연보"}     ← ENG 없음
```

기관당 1콜. 트리 등장 기관이 380개이므로 **약 380콜(~2분)로 기관명이 전부 채워진다.**

→ `reports/KOSIS_org_name_보강_계획서.md`가 P5(`MT_OTITLE` 전수 ~20,000콜)로 풀려던 문제다. 같은 문서 §5의 "의사 기관 코드 `999`/`999S` 상수 매핑 별도 정의"도 불필요해진다(`999`가 정상 응답). **P5의 존재 이유에서 "기관명 확보"는 빠지고 `MT_OTITLE` 표 수집 목적만 남는다.**

## 4. 중복 표 처리 — 경로만 다르다 (실측)

### 4.1 뷰 간 필드 동일성

`MT_TM1_TITLE`(대상별) 465건 전수와 `MT_ZTITLE` A(인구) 2,366건 전수를 각각 크롤해 교집합 51건을 필드 단위로 비교했다.

```
path 외 필드가 다른 표: 0건 / 51건
필드별 불일치: {}
```

`ORG_ID`·`TBL_ID`·`TBL_NM`·`STAT_ID`·`SEND_DE`·`REC_TBL_SE` **전부 동일**했다. 뷰마다 달라지는 것은 `VW_CD`/`VW_NM`과 경로뿐이다:

```
TM1 : VW_CD=MT_TM1_TITLE  VW_NM=테마별통계(대상별)  path=외국인 > 외국인 체류 및 이동  ids=A09 > A0903
Z   : VW_CD=MT_ZTITLE     VW_NM=국내통계 주제별     path=인구 > 국제인구이동통계       ids=A > A_2
```

→ **병합 시 경로 외 필드는 아무 뷰 값이나 써도 된다.** 단 뷰별 크롤 시점이 다르면 `send_de`가 갈릴 수 있으므로 **최신값 채택 + 불일치 건수 로깅**(불일치는 그 자체가 드리프트 신호).

### 4.2 같은 뷰 안에서도 한 표가 여러 경로에 걸린다

```
[ZTITLE-A] TX_11025_A020_A 한국국적을 취득한 자-혼인 귀화자(계)
  - 인구 > 지방자치단체외국인주민현황 > 2015년 이후(11월1일 기준) > ...  | A > A_8 > 110_11025_2015 > ...
  - 인구 > 지방자치단체외국인주민현황 > 2006~2015년(1월1일 기준) > ...   | A > A_8 > 110_11025_2006 > ...
[TM1] DT_1DA7088S 행정구역(시도)/성별 실업자
  - 남성                 | 101_A11
  - 여성 > 여성의 경제활동 | A06 > A0601
```

실측 건수: TM1 8건, ZTITLE-A 7건.

**이것이 현재 트리의 리프 265,213 vs 유니크 265,094 = 119건 차이의 정체다.** 지금까지 설명 없이 방치됐던 수치다.

→ `category_paths`는 **뷰당 단일 경로가 아니라 경로 리스트**여야 한다.

또한 `2015년 이후(11월1일 기준)` 같은 분류명은 언제든 바뀔 수 있다. **경로를 이름만이 아니라 `LIST_ID` 배열로도 저장해야 하는 근거**다.

### 4.3 채우는 방식 — 표 1건 = 레코드 1건, 경로는 전부

```json
{"table_key": "101:DT_1DA7088S",
 "org_id": "101", "tbl_id": "DT_1DA7088S",
 "tbl_nm": "행정구역(시도)/성별 실업자",
 "stat_id": "...", "send_de": "2026-07-15", "rec_tbl_se": "N",
 "view_codes": ["MT_ZTITLE", "MT_TM1_TITLE"],
 "category_paths": {
   "MT_ZTITLE":    [{"names": ["노동","경제활동인구조사"], "ids": ["D","D_1"]}],
   "MT_TM1_TITLE": [{"names": ["남성"],                  "ids": ["101_A11"]},
                    {"names": ["여성","여성의 경제활동"],   "ids": ["A06","A0601"]}]
 }}
```

필드는 어차피 같으니 중복 저장할 이유가 없고, 경로는 버리면 복구가 안 된다.

> 임베딩 텍스트에 어느 경로를 넣을지(`primary_path`)와 코퍼스 분리(`corpus`)는 선행 계획서 §3.3/§3.3.1의 결정을 따른다. 본 문서는 **저장 계층**만 규정한다.

## 5. 기존 스크립트 재사용 가능 여부

### 5.1 `kosis_tree_crawler.py` — 불가능. 새로 쓴다

| 위치 | 문제 |
|---|---|
| `kosis_tree_crawler.py:30-39` | `TOP_CATEGORIES`에 `MT_ZTITLE` 대분류 30개 **하드코딩** |
| `kosis_tree_crawler.py:93` | `list_tables(parent_id=parent)` — **`vw_cd`를 안 넘겨** 항상 `MT_ZTITLE` |
| `kosis_tree_crawler.py:27` | 단일 출력 파일 고정, `result[top_id]` 구조라 뷰 혼재 시 키 충돌 |
| `kosis_tree_crawler.py:109-121` | `err` 응답을 표 없음으로 오해해 서브트리 유실(선행 계획서 §1.3) |

여기에 필드 5개 누락(§3.1)까지 더하면 `--views` 인자 하나 붙이는 수준이 아니다. 기존 파일은 남겨두고 `kosis_tree_crawler_v5.py`를 새로 쓴다.

### 5.2 `kosis_meta_enricher.py` — 함수 하나만 교체하면 그대로 쓴다

**`org_id:tbl_id` 단위로 동작하고 뷰 개념이 아예 없다.** 아래는 전부 유지:

- `RateLimiter`(분당 180, 스레드 안전) — v5 크롤러가 오히려 이 패턴을 가져다 써야 한다
- `call_with_retry` + `err 40` 65초 쿨다운
- 체크포인트·재개 (`load_done_keys`)
- ITM / PRD / 조건부 UNIT 파싱, 병렬 워커

고칠 것은 트리 구조에 결합된 `iter_tables()`(`kosis_meta_enricher.py:115-146`) 하나다:

```python
def iter_tables_from_master(path, views=None):
    """kosis_table_tree_master_v5.jsonl 을 읽어 표 단위 유니크 목록을 만든다."""
    seen = {}
    with open(path, encoding="utf-8") as f:
        for line in f:
            r = json.loads(line)
            if views and not (set(r["view_codes"]) & set(views)):
                continue
            seen.setdefault(r["table_key"], r)
    return list(seen.values())
```

- `--categories`(대분류 ID 기준)는 뷰 개념이 없어 의미를 잃는다 → `--views`로 대체
- `--reuse-meta <path>` 추가 (§6)

**순서가 중요하다.** 메타 보강을 뷰별로 돌리면 중복 표에 `getMeta`를 여러 번 부르게 된다. 반드시 **뷰 전수 → 병합(표당 1줄) → 마스터에 대해 1회**.

## 6. 기존 산출물 재활용 — 메타가 55시간을 줄인다

### 6.1 `kosis_table_tree.json` — 크롤 시간 단축 불가

BFS는 **노드를 호출해야 그 자식을 알 수 있다.** 이미 가진 리프 목록으로는 중간 노드를 건너뛸 수 없으므로 목록 API 호출량은 그대로다. 게다가 기존 트리에는 **`LIST_ID`가 저장돼 있지 않아**(§3.1) 중간 지점부터 재개하는 것조차 불가능하다.

쓸 수 있는 용도는 둘:
- **diff 기준선** — 재크롤 결과와 대조해 신규/삭제 표 산출. 삭제분은 `status: retired` 마킹(삭제 금지, 과거 검증 이력 보존)
- **뷰 밖 표 진단** — 신규 뷰 수집분과 대조해 §1의 갭을 좁히는 데 사용

### 6.2 `kosis_table_meta_v4.jsonl` — 핵심 자산

메타 보강은 표당 `getMeta` 2~3콜로 파이프라인에서 압도적으로 비싸다.

| 시나리오 | 대상 표 | 호출 | 시간(180/분) |
|---|---|---|---|
| 전량 재보강 | 273,919 | ~684,800 | **~63시간** |
| **`meta_v4` 재활용** | 신규 8,825 + 변경분 X | (8,825+X)×2.5 | X=10%(26,509) 가정 시 **~8시간** |

265,094건이 이미 `dimensions`/`items`/`units`/`periods`/`latest_period`를 갖고 있다. 표의 차원·항목 구조는 자주 바뀌지 않으므로 **갱신되지 않은 표는 기존 메타를 그대로 승계**하면 된다.

**단, 재활용에는 `SEND_DE`가 필요하다.** `kosis_table_meta_v4.jsonl`에는 `fetched_at`(수집 시각, 2026-07-23 전후)이 있으나 **표의 갱신일이 없어 "이 메타가 아직 유효한가"를 판정할 수 없다.**

```
send_de (P6에서 새로 수집)  <=  fetched_at (meta_v4)   →  기존 메타 승계, getMeta 생략
send_de                     >   fetched_at             →  재보강 대상
status == "error" (12건)                               →  무조건 재시도
```

변경분 비율 X는 아직 미측정이다. **P6 직후 호출 0으로 산출되며**, 그 값으로 P8 일정을 확정한다. 원하면 P1 단계에서 노드 50개 표본(~50콜, 1분)으로 미리 추정할 수 있다.

### 6.3 `kosis_catalog_v4.jsonl` — 재빌드 대상

트리+메타 조인 결과물이라 원본이 바뀌면 다시 만들어야 한다. 다만 `doc_meta_text` 토큰 통계 등 **비교 기준선**으로는 유효하다.

### 6.4 그래서 P6(전체 재크롤)의 정당화는 여기에 있다

P6은 목적이 둘 겹쳐 있고 필요 범위가 다르다:

| 목적 | 필요 범위 | 비용 |
|---|---|---|
| 결함 검증(선행 계획서 §1.3) | **지역통계 V만** | ~16,577콜 / ~1.5h |
| 필드 백필(§3) → 메타 재활용(§6.2) | **30개 대분류 전부** | ~27,000콜 / ~2.5h |

선행 계획서에서 표본 6개 대분류가 **전부 재현**됐으므로, 결함만 놓고 보면 전체 재크롤 근거는 약하다. 전체 범위를 요구하는 것은 필드 백필이고, 그 정당화는 P6이 아니라 **P8**에 있다 — **2.5시간을 써서 63시간을 8시간으로 줄이는 거래**다.

`rec_tbl_se`·`path_ids`는 같은 호출에 묻어가는 덤이며, 그것들만으로는 2.5시간을 정당화하지 못한다.

## 7. 폴더·명명규칙

**v5 작업물은 전용 폴더 두 개에만 넣는다. 기존 `src/*.py`·`data/*`는 건드리지 않는다.**

```
src/크롤링_v5/     ← v5 스크립트 전부
data/크롤링_v5/    ← v5 산출물 전부
```

폴더 안에서도 파일명에 `_v5`를 유지한다 — 파일을 폴더 밖으로 옮기거나 다른 문서에서 인용할 때 세대가 그대로 따라오게 하기 위해서다.

### `kosis_client_v5.py`에 대한 메모

원본 `src/kosis_client.py`를 **복사**한 것이며 원본은 그대로 둔다. 기존 3개 파일(`kosis_tree_crawler.py`·`kosis_meta_enricher.py`·`kosis_api_probe.py`)이 원본을 import하고 있어 동작을 보존해야 하기 때문이다.

> **유지보수 주의**: `_loads_lenient`의 백슬래시 교정 로직이 원본과 두 벌로 존재한다. KOSIS 응답 파싱 버그를 또 만나면 **두 파일 다 고쳐야 한다.** v4 파이프라인을 은퇴시킬 때 원본을 지우면서 해소한다.

> **`v5`의 정의**: 13개 뷰 전수 + 결함 수정 크롤러로 만든 것만 `v5`라 부른다. 부분 수집분을 `kosis_table_tree_master_v5.jsonl`로 저장하지 않는다 — 뷰별 파일은 중간에 쌓이되, 병합 마스터는 13개 뷰가 모두 `status == "completed"`가 된 뒤에만 생성한다.

### 왜 뷰별 파일로 나누나

1. **재개 단위가 뷰다.** 545건(수분)부터 265,094건(2.5시간)까지 편차가 크다. 한 파일에 몰면 지역통계 도중 죽었을 때 끝난 뷰까지 흔들린다.
2. **완주 판정이 뷰 단위다.** `status`/`failed_nodes`를 뷰마다 남겨야 한다.
3. **크기.** 현재 트리가 `MT_ZTITLE` 하나로 100MB다. 13개를 합치면 뷰 하나 확인하려고 매번 전체를 파싱해야 한다.
4. **병합이 단순 union이 아니다.** `view_codes`/`category_paths` 조립이므로, 원본을 뷰별로 남겨야 병합 로직 수정 시 재크롤 없이 다시 돌릴 수 있다.

단점은 "표 하나가 어느 뷰들에 속하는가"를 알려면 13개 파일을 조인해야 한다는 것인데, 그건 병합 단계에서 한 번만 하고 결과를 마스터에 굳히면 된다.

## 8. 크롤러 요구사항 (`kosis_tree_crawler_v5.py`)

선행 계획서 R1~R8을 승계하고 R9~R12를 추가한다.

| # | 요구사항 | 이유 |
|---|---|---|
| R1 | `--views` 인자로 vwCd 지정, 뷰별 독립 출력 | 13개 뷰를 같은 코드로 |
| R2 | 노드 단위 재시도(최대 4회, 지수 백오프) + `err 40` 시 65초 쿨다운 | `kosis_meta_enricher.py`의 `call_with_retry` 재사용 |
| R3 | 실패 노드를 `data/크롤링_v5/kosis_crawl_failures_v5.jsonl`에 영구 기록 | 사후 복구 |
| R4 | `--retry-failures` 모드 | 실패 노드만 재시도 |
| R5 | 노드 단위 체크포인트 | 지역통계 중단 시 통째 재시작 방지 |
| R6 | 공유 `RateLimiter`(분당 180) | 목록 API도 같은 키 한도 |
| R7 | `pending==0 and failed==0`일 때만 `status="completed"` | 완주 판정 |
| R8 | 루트 하드코딩 금지, `parentListId=""`로 조회 | 분류 개편 자동 반영 |

### 선행 필수: `kosis_client.list_tables()` 수정

data = _loads_lenient(res.text)
if isinstance(data, dict) and "err" in data:
