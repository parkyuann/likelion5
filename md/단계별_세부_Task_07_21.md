# 단계별 세부 Task 정리 (v2 아키텍처 기준)

작성일: 2026-07-21 · 기준 문서: [전체_아키텍쳐_07_21.md](전체_아키텍쳐_07_21.md) (v2)

> 목적: 현재 코드 자산을 실측한 뒤, v2 아키텍처까지 남은 작업을 단계(실전1/실전2/최종)·세부 Task로 분해한다.
> 각 Task는 **목적 / 입력→산출물 / 대상 파일 / 완료조건(DoD) / 측정지표**를 갖는다.

## 실전1 — 주장 추출·스키마화·사전분류 (마무리 단계)

### T1-1. source_scope 분류기 완성 및 지표 확정
- 목적: 사전 필터의 분류 품질을 지표로 고정 (하드게이트 전환 판단 근거)
- 입력→산출물: `claims_v1.jsonl` → source_scope 예측 + 혼동행렬
- 대상 파일: `src/source_scope_classifier.py`(수정), `tests/test_source_scope_classifier.py`(보강)
- DoD: validation300에서 정밀도/재현율 리포트 산출, 오탐 사례 로깅
- 지표: source_scope 정밀도/재현율, claim_class F1

### T1-2. 사전 필터를 하드게이트→디부스트로 변경 (v2 반영)
- 목적: 검색 앞단 리콜 손실 방지
- 입력→산출물: 분류 결과 → `verifiability_prefilter` = 검증시도 / **강등** / 제외 (3값)
- 대상 파일: `src/convert_claim_listform_to_schema.py` 또는 사전필터 로직 위치(수정), `retrieval_schema.py`(enum 확장)
- DoD: 미충족 claim이 탈락하지 않고 강등 플래그로 검색에 진입, 사유 로깅
- 지표: 디부스트 vs 하드게이트 Recall 손실 비교(T2-4에서 측정)

### T1-3. 스키마 필드 v2 확장
- 목적: abstention·시간정합성·허용오차를 데이터 모델에 반영
- 대상 파일: `src/retrieval_schema.py`(수정)
  - `Claim.overall_status` 추가: `VERIFIED/REFUTED/UNVERIFIABLE/PARTIAL`
  - `ClaimObservation.rounding_hint`(근사표현 여부) — 기존 `approximation_qualifier` 재활용 검토
  - `ClaimTableMapping.align_status`: `ALIGNED/DIM_MISSING/PERIOD_MISMATCH/ITEM_AMBIGUOUS/NO_CELL`
  - `KOSISTable.latest_period`(최신 공표 시점)
  - `sequence` 사용 규약 주석 명시
- DoD: `validate_claim/table/mapping`에 신규 enum 검증 추가, 기존 테스트 통과

## 실전2 — 검색 (색인 → 하이브리드 → 리랭커)

### T2-1. 표 문서화 분리 (document_text 개선, v2 반영)
- 목적: 임베딩 희석·토큰 초과 방지
- 입력→산출물: `kosis_table_tree.json` → `kosis_catalog_v2.jsonl`
  - `doc_meta_text` = tbl_name + category_path + 핵심 차원명 (임베딩 대상, 짧게)
  - `doc_item_index` = 전체 항목명·차원값 (BM25/메타 필터 전용)
- 대상 파일: `src/build_kosis_catalog.py`(수정)
- 전제: 차원·항목명은 tree에 없으면 KOSIS API(`kosis_client.py`)로 보강 필요 → 서브태스크 T2-1a
- DoD: 두 필드 분리 저장, `doc_meta_text` 토큰수 임베딩 한도 이내(HCX v2 한도 확인)
- 지표: 평균 토큰 길이, 한도 초과 표 비율 0%

### T2-2. Qdrant 색인기 구축
- 목적: dense + sparse + metadata 색인
- 입력→산출물: `kosis_catalog_v2.jsonl` → Qdrant 컬렉션
- 대상 파일: `src/kosis_indexer.py`(신규)
  - dense: `hcx_embedding_client.py` 재사용(doc_meta_text 임베딩)
  - sparse: BM25 (doc_item_index 포함)
  - metadata: org_id, period_types, dimensions, units, version_status, latest_period
- 의존성: `qdrant-client` (`requirements.txt` 추가)
- DoD: 전체 표 upsert 성공, 컬렉션 카운트 = 유니크 표 수, 재색인 idempotent
- 지표: 색인 소요시간, 임베딩 호출 수/비용

### T2-3. 하이브리드 검색기 구축
- 목적: 3경로 합집합 후보풀 + 메타 프리필터
- 입력→산출물: 정규화 claim → 후보 N개
- 대상 파일: `src/kosis_retriever.py`(신규)
  - ① HyDE(`predicted_tbl_nm`) 임베딩 검색 — HCX 생성부 포함
  - ② 정규화 원주장 임베딩 검색
  - ③ 지표어 BM25 검색
  - 메타 프리필터(org_id 등)
- DoD: 후보 mapping을 `ClaimTableMapping`(dense/sparse_score 기록)으로 출력
- 지표: **Recall@N** (골드 표가 후보에 포함), 경로별 기여도

### T2-4. HyDE ablation + 리랭커 비교
- 목적: ① HyDE 경로가 순이득인지, 리랭커가 순이득인지 실측
- 입력→산출물: 후보풀 → 리랭킹 top K
- 대상 파일: `src/kosis_retriever.py`(리랭커 통합), BGE-reranker-v2-m3
- 의존성: `FlagEmbedding` (`requirements.txt` 추가)
- DoD: (a) HyDE 유/무 Recall@N 비교표, (b) 리랭커 단독 vs +리랭커 Recall@K/MRR 비교표
- 지표: Recall@K, MRR, nDCG (`retrieval_harness.py`의 지표 산출부 재사용/확장)

### T2-5. 검색 골드셋 확정
- 목적: 위 지표의 신뢰 근거 (silver→gold 승격)
- 입력→산출물: `retrieval_eval_claims_v0_codex.csv`(silver) → 사람 검토 gold
- 대상 파일: `data/retrieval_eval_*`(라벨), `src/create_retrieval_eval_set.py`(필요시 수정)
- DoD: 최소 20~30건 표 단위 gold 확정 (T2-3~T2-4 지표 계산에 사용)

## 최종 — 정렬·검증·설명 (핵심 난제, 우선 투자)

### T3-1. 시간 정합성 게이트
- 목적: 미공표 시점 주장을 조기에 UNVERIFIABLE로 분기
- 입력→산출물: observation.period vs table.latest_period → 게이트 결과
- 대상 파일: `src/claim_table_aligner.py`(신규, 진입부) 또는 별도 모듈
- DoD: period > latest_period 시 `align_status=PERIOD_MISMATCH`, overall_status 후보 UNVERIFIABLE
- 지표: 미공표 케이스 정탐률

### T3-2. 차원·시점 정렬기 (셀 지정)
- 목적: observation → 표의 정확한 (항목·시점·차원) 셀 매핑
- 입력→산출물: 선택 표 + observation → matched_dimensions/item/period + align_status
- 대상 파일: `src/claim_table_aligner.py`(신규)
- 실패 유형 분류: `DIM_MISSING / PERIOD_MISMATCH / ITEM_AMBIGUOUS / NO_CELL`
- DoD: 셀 단위 gold 대비 정렬 정확도 리포트, 실패 유형 분포 산출
- 지표: 셀 정렬 정확도, align_status 분포

### T3-3. KOSIS 셀 조회
- 목적: 정렬 성공 셀만 실제값 조회
- 입력→산출물: matched_* → KOSIS API 셀 값
- 대상 파일: `src/kosis_client.py`(조회 함수 확장)
- DoD: observation 개수만큼 조회, rate limit 대응 배치/재시도
- 지표: 조회 성공률, API 호출 수

### T3-4. 결정론적 검증기
- 목적: change_type별 계산 + 허용오차 판정 (LLM 판정 금지)
- 입력→산출물: 주장값 vs 실제값 → `list_alignment_status` + overall_status
- 대상 파일: `src/verifier.py`(신규)
  - change_type(증감률/비교/순위 등)별 계산식
  - rounding_hint 기반 tolerance 규칙
  - 셀 없음/매핑 불가 → UNVERIFIABLE (환각 금지)
- DoD: gold 대비 ALIGNED 정확도 + UNVERIFIABLE 재현율 리포트
- 지표: ALIGNED 정확도, UNVERIFIABLE 재현율

### T3-5. LLM 설명 생성
- 목적: 확정 수치·시점·출처만 근거로 인용형 서술
- 입력→산출물: 검증 결과 → 설명 텍스트
- 대상 파일: `src/explanation_generator.py`(신규)
- DoD: UNVERIFIABLE은 "KOSIS로 확인 불가" 사유 포함, 근거 밖 수치 인용 0건
- 지표: 근거 이탈(hallucination) 발생률, 인용 정확도

## 착수 순서 (v2 반영)

```
[실전1 마무리]  T1-1 → T1-2 → T1-3
[실전2]         T2-5(gold) → T2-1 → T2-2 → T2-3
                → T-INT(관통) → T2-4(리랭커/HyDE 비교)
[최종]          T3-1 → T3-2(셀 정렬, 최우선 투자) → T3-3 → T3-4 → T3-5
```

## 의존성·리스크 요약
- **T2-1a(차원·항목 보강)**: tree에 차원/항목명이 없으면 KOSIS API 대량 호출 필요 → 실전2 최대 선행 리스크
- **T3-2(셀 정렬)**: 프로젝트 최대 난제, 실패유형 gold 라벨 확보가 관건
- **비용/처리량**: 기사당 HCX 호출(스키마화+HyDE+임베딩+설명) 수 · KOSIS rate limit → 각 Task DoD에 호출 수 기록
