## 1. 이게 뭔가요

뉴스 기사 속 **수치 주장**을 국가통계(KOSIS)와 대조해 검증하는 파이프라인의 **프론트엔드(결과 표시 화면)** 입니다.
백엔드(파이썬 파이프라인)는 이미 있고, 이 프로젝트는 그 결과를 사람이 보기 쉽게 보여주는 웹 UI만 담당합니다.

- **현재 상태**: 백엔드 연결 전. **mock(가짜) 데이터**로 화면·동작을 먼저 구현한 프로토타입.
- **스택**: React 19 + Vite (JavaScript). 외부 UI 라이브러리 없음, CSS 직접 작성.

## 4. 지금까지 구현한 기능 (UI 동작)

1. **기사 입력** — 텍스트 영역에 기사 전문을 붙여넣고 `검증하기`.
2. **실시간 진행 로그** — 검증 중, 파이프라인 단계가 **한 줄씩 아래로 누적**되는 터미널풍 로그.
   - 순서: `[파싱] → [표 매핑] 후보 5개 → [재점수] 리랭커 → [RAG Reasoning] 판정 → [표연산] 계산 → 판정 완료`
   - 문장별로(`문장 1/3`, `문장 2/3`…) 반복. 완료 줄 ✓, 진행 줄 ▸.
3. **판정 요약** — 결과 상단에 `일치 / 불일치 / 검증 불가능` **건수** 카드.
4. **원문 + 하이라이트** — 기사 원문을 그대로 보여주되, 검증 대상 수치 문장에 **밑줄 + 옅은 배경색**.
   - 일치=초록 실선, 불일치=빨강 실선, 검증 불가능=회색 점선.
5. **문장 클릭 → 상세** — 클릭하면 그 문장이 **자기 줄로 분리되어 도드라지고**, 아래에 상세가 펼쳐짐:
   - 판정 라벨
   - **RAG Reasoning 최종 답변**(자연어)
   - **표연산(계산식)** 예: `(11,694,600.8 − 11,252,865.6) ÷ 11,252,865.6 × 100 = +3.93%`
   - **근거 표 링크**(클릭 시 KOSIS 표로 이동) + **📍경로**
   - **`▸ 고려한 통계표 후보 5개`** 펼치기 — 순위·이름·score·상태(선택/지표없음), 1위=선택 표 강조.

## 5. 판정 종류 (4가지)

| verdict | 의미 | 표시 |
| --- | --- | --- |
| `match` | 일치 | 초록 |
| `mismatch` | 불일치 | 빨강 |
| `notfound` | 검증 불가능 · **매칭 실패**(후보는 있으나 지표 매칭 실패, 개선 가능) | 회색 |
| `outofscope` | 검증 불가능 · **대상 밖**(전망·개별사례 등, 사전 분류에서 제외) | 회색 |

## 6. 백엔드 연결 시 해야 할 일 (가장 중요)

지금 `App.jsx`는 두 부분만 실제 백엔드로 바꾸면 됩니다.

### (A) 검증 요청 → 결과 받기
`handleVerify()` 안의 `mockAnalyze(article)` + `setTimeout` 진행 흉내 부분을 실제 API 호출로 교체.
백엔드가 돌려줄 **문장별 결과 배열** 형태(프론트가 기대하는 계약):

```json
[
  {
    "text": "...23만 명으로 집계됐다.",   // 원문 문장(그대로)
    "verifiable": true,                  // 검증 대상 여부
    "verdict": "match",                   // match | mismatch | notfound | outofscope
    "answer": "통계청 ... 일치합니다.",    // RAG Reasoning 자연어 판정
    "calc": "(a − b) ÷ b × 100 = +3.93%",// 표연산(없으면 null)
    "table": {                             // 근거 표(없으면 null)
      "name": "자산별 생산자본스톡(명목, 연말기준)",
      "orgId": "101",
      "tblId": "DT_104Y260",
      "path": "통계청 › ... › 2024년"
    },
    "candidates": [                        // 고려한 후보 5개(없으면 null)
      { "rank": 1, "key": "101:DT_104Y260", "name": "...", "score": 6.0, "status": "선택" },
      { "rank": 2, "key": "301:DT_200Y134", "name": "...", "score": 2.0, "status": "지표없음" }
    ]
  },
  { "text": "정부는 ...", "verifiable": false }   // 숫자 없는 일반 문장
]
```

- `table.orgId` / `table.tblId` → KOSIS URL은 프론트가 조립: `https://kosis.kr/statHtml/statHtml.do?orgId=..&tblId=..`
- `candidates[].key`는 `"orgId:tblId"` 형식(프론트가 분리해서 링크 생성).
- 문장 분리를 백엔드에서 하면 프론트의 `splitSentences`는 안 써도 됨(백엔드 배열을 그대로 렌더).

### (B) 실시간 진행 로그
현재는 mock이 단계를 흉내냅니다. 실제로는 백엔드가 단계를 **스트리밍**으로 push하면 그대로 연결:
- **SSE(Server-Sent Events)** 또는 **WebSocket** 권장. 서버가 `"[재점수] 리랭커..."` 같은 줄을 보낼 때마다 `setLogs(prev => [...prev, line])`.
- 스트리밍이 부담이면 폴링으로 대체 가능.

### API 서버(별도 작업)
파이썬 파이프라인을 **FastAPI**로 감싸 `POST /verify` 엔드포인트를 만들어야 함(아직 없음).
개발 중 CORS 및 프론트→백 주소는 Vite 프록시(`vite.config.js`) 또는 `fetch("http://localhost:8000/verify")`로 처리.
