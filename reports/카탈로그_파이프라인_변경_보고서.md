# KOSIS 카탈로그 파이프라인 변경 보고서 (v1 → v2)

> 작성일: 2026-07-28
> 범위: 표 목록 크롤 → 카탈로그 생성 파이프라인이 기존(v1)에서 현재(v2)로 어떻게
> 바뀌었는지 정리한다. 관련 코드: `kosis_tree_crawler.py`, `kosis_meta_enricher.py`,
> `build_kosis_catalog.py`(v1), `kosis_catalog_builder.py`(v2).

---

## 0. 한눈에 보기

| 구분 | 기존 (v1) | 현재 (v2) |
|---|---|---|
| 단계 수 | 2단계 (트리 → 카탈로그) | **3단계 (트리 → 메타 보강 → 카탈로그)** |
| API 호출 | 트리 크롤만 | 트리 크롤 + **표당 getMeta(ITM/PRD/UNIT)** |
| 검색 텍스트 | `document_text` 1필드 | **`doc_meta_text` + `doc_item_index` 2필드 분리** |
| 부가정보(payload) | 없음 | `units` · `dimensions` · `period_types` · `latest_period` · `org_name` |
| 카탈로그 빌더 | `build_kosis_catalog.py` | `kosis_catalog_builder.py` |
| 산출물 | `kosis_catalog_v1.jsonl` | `kosis_catalog_v2.jsonl` (파일명은 세대별로 v4 등 가능) |

핵심: **"표 목록만 담던 카탈로그"에서 "표의 속살(차원·항목·단위·시점)까지 담고 검색
용도별로 필드를 분리한 카탈로그"로 진화**했다. 대가로 중간에 시간이 오래 걸리는 메타 보강
크롤 단계가 추가됐다.

---

## 1. 기존 흐름 (v1) — 2단계

```
① kosis_tree_crawler.py
      │  statisticsList.do 로 대분류 30개를 BFS로 훑어 '표 목록' 수집
      ▼
   data/kosis_table_tree.json        표당: org_id, tbl_id, tbl_nm, stat_id, path
      │
② build_kosis_catalog.py
      │  트리만 정규화 (KOSIS API 추가 호출 없음, 차원·항목 생성 안 함)
      ▼
   data/kosis_catalog_v1.jsonl       표당: document_text 한 필드
```

**v1 `document_text`의 형태와 한계**
```
"누적 혼인 비율 101 2025010 인구 인구동태패널통계 혼인·출산 비율"
              ▲ org_id·stat_id 숫자(임베딩 노이즈)   ▲ 경로만, 차원·항목 없음
```
- 한 필드를 dense 임베딩과 sparse(BM25)가 함께 써서 요구가 상충한다 — 임베딩은 짧고
  의미가 밀집해야 하고, BM25는 매칭 토큰이 많아야 한다.
- `101`, `2025010` 같은 숫자 ID가 벡터만 흐리고 의미에 기여하지 못한다.
- 트리에 없는 정보(차원·항목·단위·시점)를 아예 담지 못한다.

---

## 2. 현재 흐름 (v2) — 3단계 (중간에 '보강' 추가)

```
① kosis_tree_crawler.py             ← 그대로 재사용 (변경 없음)
      ▼
   data/kosis_table_tree.json
      │
★ kosis_meta_enricher.py            ← ★ 새로 추가된 단계
      │  표마다 getMeta ITM+PRD+(조건부)UNIT 호출
      │  → 차원(dimensions)·항목(items)·단위(units)·시점(periods) 확보
      ▼
   data/kosis_table_meta_v2.jsonl    표당: dimensions, items, units, period_types, latest_period
      │
② kosis_catalog_builder.py          ← build_kosis_catalog 의 v2판 (트리 + 메타 + 기관명 합침)
      ▼
   data/kosis_catalog_v2.jsonl       표당: doc_meta_text + doc_item_index + payload
```

**v2 카탈로그의 필드 분리**
```
doc_meta_text  : 누적 혼인 비율 | 인구 > 인구동태패널통계 > 혼인·출산 비율 | 성별, 년생별
                 └ 임베딩 전용. 표명 + 경로 + 차원'명'. 짧게 유지.
doc_item_index : 비율 전체 남자 여자 1983 1984 ... 1995
                 └ BM25 전용. 항목명 + 차원'값' 전부. 길어도 됨.
payload        : org_id, org_name, units, dimensions, period_types, latest_period
                 └ 텍스트 검색이 아니라 메타 프리필터에 쓰는 값.
```

---

## 3. 무엇이 바뀌었나 — 핵심 3가지

### ① 중간에 '메타 보강' 단계가 신설됨 (`kosis_meta_enricher.py`)

기존은 트리 → 바로 카탈로그였지만, 현재는 **트리 → getMeta 보강 → 카탈로그**로 한 단계가
끼어들었다. 트리에 없던 **차원·항목·단위·시점**을 표마다 KOSIS API로 긁어온다.

- 호출 비용: 표당 ITM(1) + PRD(1) + 조건부 UNIT(0~1) = 2~3회. 전체 약 49~73시간 규모.
- 트리 크롤(카테고리 노드당 1회)과 달리 **표당 개별 호출**이라 시간이 크다.

### ② 카탈로그 빌더 교체 (`build_kosis_catalog.py` → `kosis_catalog_builder.py`)

| 항목 | v1 빌더 | v2 빌더 |
|---|---|---|
| 입력 | 트리 1개 | 트리 + **메타(meta_v2.jsonl)** + 기관명 |
| 검색 텍스트 | `document_text` 1개 | `doc_meta_text` + `doc_item_index` 2개 분리 |
| 기관명 | 없음(org_id 숫자만) | `org_name` 추가 |
| payload | 없음 | units, dimensions, period_types, latest_period |
| 토큰 통계 | 없음 | 임베딩 한도(8,192) 초과 표 집계 등 manifest |

**왜 두 필드로 나눴나**: 차원값은 표당 수백~수만 개(예: 읍면동 6천 개)라 임베딩에 넣으면
표의 정체가 목록에 파묻히고 임베딩 토큰 한도(8,192)도 넘긴다. 반대로 BM25에는 "종로구"
같은 토큰이 인덱스에 있어야 매칭되므로 넣어야 한다. 요구가 반대라 분리했다.

### ③ 원본을 지우지 않고 '병행'으로 구성

- `kosis_tree_crawler.py`는 1단계로 **그대로 재사용**한다(변경 없음).
- `build_kosis_catalog.py`(v1)는 **삭제하지 않고 남겨둔다**. 아직 아래 코드가 v1
  산출물(`kosis_catalog_v1.jsonl`)과 그 `document_text` 필드에 의존하기 때문이다.
  - `src/retrieval_harness.py` — 어휘 기반 검색 baseline. 기본 카탈로그가
    `kosis_catalog_v1.jsonl`이고 `document_text` 토큰 겹침으로 후보를 생성한다.
  - `src/kosis_eda.py` — `kosis_catalog_v1.jsonl`을 읽어 EDA 통계를 낸다.
- 따라서 v1을 없애려면 위 소비자 코드를 v2 필드(`doc_meta_text`/`doc_item_index`)로
  먼저 이관해야 한다. 현재는 **v1·v2 공존**이 정상 상태다.

---

## 4. 산출 파일 대응표

| 단계 | 기존 (v1, 유지) | 현재 (v2, 신규) |
|---|---|---|
| 표 목록 크롤 | `kosis_tree_crawler.py` → `kosis_table_tree.json` | (그대로 입력) |
| 메타 보강 크롤 | — | `kosis_meta_enricher.py` → `kosis_table_meta_v2.jsonl` |
| 카탈로그 빌드 | `build_kosis_catalog.py` → `kosis_catalog_v1.jsonl` | `kosis_catalog_builder.py` → `kosis_catalog_v2.jsonl` |

> 트리 크롤은 주제별(`MT_ZTITLE`) 뷰 기준이다. 메타 보강 결과(차원·항목·단위·시점)는
> 표(`org_id:tbl_id`) 단위라 뷰와 무관하므로, 뷰를 바꿔도(예: 기관별 `MT_OTITLE`)
> 재사용할 수 있다 — 트리만 다시 크롤하면 된다.

---

## 5. 요약

- 파이프라인이 **2단계 → 3단계**로 늘었고, 늘어난 것은 중간의 **메타 보강 크롤**이다.
- 카탈로그는 `document_text` 1필드에서 **임베딩용/BM25용 2필드 + payload**로 재구성됐다.
- 원본(`kosis_tree_crawler.py`, `build_kosis_catalog.py`)은 그대로 두고 병행 구축했으며,
  v1 산출물은 아직 `retrieval_harness.py`·`kosis_eda.py`가 사용 중이라 **삭제 불가**다.
