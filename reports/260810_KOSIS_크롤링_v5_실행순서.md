## [1] `kosis_client_v5.py` — 라이브러리

직접 실행하지 않는다. 다른 스크립트가 import 한다.

원본 `src/kosis_client.py` 를 복사한 것으로, **`list_tables()` 하나만 다르다**:
- `err` 응답을 검사한다 (`err 30`만 빈 리스트로 흡수, 나머지는 예외)
- `vw_cd`·`parent_id` 에 기본값이 없다 (필수 인자)

동작 확인:

```bash
venv/Scripts/python.exe -c "import sys; sys.path.insert(0,'src/크롤링_v5'); from kosis_client_v5 import list_tables; print(len(list_tables('MT_RTITLE','')))"
```

## [2] `kosis_tree_crawler_v5.py` — 뷰별 트리 크롤

### 프리셋

| 프리셋 | vwCd | 비고 |
|---|---|---|
| `official` | 11개 | 개발가이드 게재분(영문 미러 제외) |
| `web_only` | `MT_GTITLE03`, `MT_RTITLE01` | 웹 메뉴엔 있으나 문서 미게재 |
| `web` | 13개 | 위 둘 합집합 |
| `unofficial` | `MT_PTITLE`, `MT_ATITLE01`, `MT_ATITLE02` | 웹·문서 모두 없음 |
| `mirror` | `MT_ETITLE` | 영문 |

### 실행

```bash
venv/Scripts/python.exe src/크롤링_v5/kosis_tree_crawler_v5.py --preset official
```

뷰를 직접 지정하려면:

```bash
venv/Scripts/python.exe src/크롤링_v5/kosis_tree_crawler_v5.py --views MT_ZTITLE,MT_OTITLE
```

진행 상황만 보기 (API 호출 없음):

```bash
venv/Scripts/python.exe src/크롤링_v5/kosis_tree_crawler_v5.py --status
```

실패 노드만 재시도:

```bash
venv/Scripts/python.exe src/크롤링_v5/kosis_tree_crawler_v5.py --retry-failures
```

### 중단·재개

**그냥 껐다 켜도 된다.** 같은 명령을 다시 실행하면 이어서 진행한다.

- 체크포인트를 200콜마다 저장한다
- 재개할 때 리프 파일이 체크포인트보다 앞서 있으면 그만큼 잘라낸다(`[TRUNC]` 로그).
  안 그러면 재크롤 구간의 표가 두 번 적재되어 `leaf_count` 가 부풀어 오른다
- 처음부터 다시 하려면 `--restart`

### 산출물

```
data/크롤링_v5/tree_v5/
  kosis_table_tree_{vwCd}_v5.json              완주본
  kosis_table_tree_{vwCd}_v5.leaves.jsonl      진행 중 리프 (append)
  kosis_table_tree_{vwCd}_v5.checkpoint.json   큐 상태
  kosis_table_tree_manifest_v5.json            뷰별 요약
data/크롤링_v5/kosis_crawl_failures_v5.jsonl   실패 노드 (전 뷰 공통, 없으면 실패 0건)
```

리프 1건의 형태:

```json
{"org_id":"101","tbl_id":"DT_1B040B3","tbl_nm":"행정구역(시군구)별 주민등록세대수",
 "stat_id":"2008001","send_de":"2026-08-09","rec_tbl_se":"N","vw_cd":"MT_ZTITLE",
 "path":["인구","주민등록인구현황"],"path_ids":["A","A_1"]}
```

### 완주 확인

`--status` 에서 뷰마다 `completed` 이고 실패 0이어야 한다. 그리고 결과 파일의 `audit` 블록이 전부 0인지 본다.

| audit 항목 | 0이 아니면 |
|---|---|
| `vw_cd_mismatch` | 요청한 뷰와 다른 응답이 왔다 |
| `skipped_visited` | 같은 노드가 두 부모 아래 — 표는 다 있으나 두 번째 경로가 누락 |
| `unknown_rows` | `TBL_ID`도 `LIST_ID`도 없는 행을 버렸다 |
| `empty_nodes` | 자식 없는 노드 + `err 30` 흡수분. 재크롤 대조로만 검증 가능 |

## [5] 뷰 병합 ✅

입력: `tree_v5/*.json` 전부 → 출력: `data/크롤링_v5/kosis_table_tree_master_v5.jsonl`

표 1건 = 레코드 1건. 뷰 간 경로 외 필드는 동일함이 실측으로 확인됐으므로(계획서 §4.1) 경로만 다중으로 담는다.

```json
{"table_key":"101:DT_1DA7088S","org_id":"101","tbl_id":"DT_1DA7088S",
 "tbl_nm":"행정구역(시도)/성별 실업자","stat_id":"...",
 "send_de":"2026-07-15","rec_tbl_se":"N",
 "view_codes":["MT_ZTITLE","MT_TM1_TITLE"],
 "category_paths":{
   "MT_ZTITLE":[{"names":["노동","경제활동인구조사"],"ids":["D","D_1"]}],
   "MT_TM1_TITLE":[{"names":["남성"],"ids":["101_A11"]},
                   {"names":["여성","여성의 경제활동"],"ids":["A06","A0601"]}]}}
```

주의:
- `category_paths` 는 **뷰 → 경로 리스트**. 한 뷰 안에서도 경로가 여럿일 수 있다(계획서 §4.2)
- `send_de` 가 뷰별로 갈리면 최신값을 쓰고 **불일치 건수를 로그로 남긴다**(드리프트 신호)
- `MT_GTITLE02` 는 제외 (위 주의 참고)

## [6] 메타 보강 ✅

입력: `kosis_table_tree_master_v5.jsonl` → 출력: `data/크롤링_v5/kosis_table_meta_v5.jsonl`

기존 `src/kosis_meta_enricher.py` 를 복사해 `iter_tables()` 만 교체한다. `RateLimiter`·`call_with_retry`·체크포인트·병렬 워커·ITM/PRD/UNIT 파싱은 그대로 쓴다.

**반드시 병합 후에 1회만 돌린다.** 뷰별로 돌리면 중복 표에 `getMeta` 를 여러 번 부른다.

핵심은 `--reuse-meta` 다. 기존 `data/kosis_table_meta_v4.jsonl`(265,094건)을 승계하면 **63시간 → 8시간**이 된다.

```
send_de <= fetched_at(meta_v4)  →  기존 메타 승계, getMeta 생략
send_de >  fetched_at            →  재보강
status == "error" (12건)         →  무조건 재시도
```
