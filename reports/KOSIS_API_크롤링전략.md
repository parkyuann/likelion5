# KOSIS API 실측 기반 크롤링 전략

작성일: 2026-07-23
근거 코드: `src/kosis_api_probe.py` (라이브 호출로 실측), `src/kosis_client.py`
목적: 기존 크롤링 산출물의 EDA가 아니라, **API를 직접 두드려 본 결과**를 근거로
"무엇을 / 어떤 엔드포인트로 / 어떤 순서로 / 얼마의 비용으로" 가져올지 결정한다.

## 1. 실측 결과 요약 — 엔드포인트별로 실제 주는 것

2026-07-23 라이브 호출 실측 (분당 200콜 제한, 키 단위).

### 1.1 `statisticsSearch.do` (키워드 검색) — 생각보다 훨씬 풍부함

"실업률" 검색 1콜의 응답 필드:

| 필드 | 내용 | 의미 |
|---|---|---|
| `ORG_ID / TBL_ID / TBL_NM / STAT_NM` | 표 식별 + 조사명 | 카탈로그 기본키 |
| `MT_ATITLE` | `노동 > 경제활동인구조사 > 실업률(...)` | **분류 경로가 그대로 옴** (트리 안 타도 됨) |
| `CONTENTS` | `시도별 성별 실업률 세종… 여자 계 남자` | **차원명+차원값 요약** — doc_item_index의 축약판 |
| `STRT_PRD_DE / END_PRD_DE` | `1999 ~ 2026` | 수록기간까지 옴 |

→ **표 1개당 1콜로 '검색 문서'에 필요한 것 대부분이 나온다.**
→ 국내 주제별뿐 아니라 **국제기구 통계(IMF 등, MT_RTITLE)도 검색에 걸린다** — 트리 크롤링이 놓친 영역.

### 1.2 `statisticsList.do` (트리) — 누락됐던 4개 서비스뷰 진입 확인

기존 `kosis_tree_crawler.py`는 `MT_ZTITLE`(국내 주제별) + 루트 `"A"`만 순회
→ 중간기록사항의 한계 1번("국제·북한 데이터 무시됨")의 원인.
**빈 `parentListId`로 호출하면 다른 뷰의 최상위가 열린다** (실측 확인):

| 서비스뷰 | 내용 | 최상위 개수 (실측) |
|---|---|---|
| `MT_RTITLE` | 국제통계 (국제통계연감 + 국제기구별) | 2 |
| `MT_BUKHAN` | 북한통계 | 6 |
| `MT_OTITLE` | 기관별 통계 (근로복지공단, 심평원 등) | **181개 기관** |
| `MT_GTITLE01` | e-지방지표 (주제별) | 12 |

### 1.3 `getMeta` (표 메타) — type별 실측 크기 (실업률 표 기준)

| type | rows | chars | 내용 | 크롤링 판단 |
|---|---|---|---|---|
| `ITM` | 22 | 4,091 | **차원·항목·단위 코드 전부** (+영문명) | ✅ 핵심, 표당 1콜 |
| `PRD` | 3 | 201 | 주기별 수록기간 (월 1999.06~2026.06 등) | ✅ 가볍고 정확 |
| `CMMT` | 2 | 284 | **시계열 단절 주석** ("세종시 분리로 충남 시계열 단절") | ✅ 검증 단계 필수 |
| `SOURCE` | 1 | 84 | 조사명·담당부서 | △ 선택 |
| `TBL` | 1 | 95 | 국문+영문 표명 | △ 선택 (검색에서 이미 옴) |
| `NCD` | **459** | **51,005** | 시점별 갱신일 전체 나열 | ❌ 과대, 스킵 |
| `UNIT` | — | — | 데이터 없음(err 30) 빈번 | ❌ ITM의 UNIT_NM으로 충분 |

### 1.4 `statisticsParameterData.do` (수치 조회) — 싸고 빠름

- 전국×계, 3개년: **3 rows, 0.31초** — 응답에 값(DT)+단위+차원명+갱신일까지 포함
- 시도 ALL × 성별 ALL × 1년: 54 rows
- → **수치는 미리 쌓아둘 필요가 없다.** 검증 시점에 표·셀을 특정해 on-demand 조회가 합리적

## 2. 전략 원칙 (실측에서 도출)

> **원칙 1. 값(수치)은 크롤링하지 않는다 — 메타만 크롤링한다.**
> getData가 0.3초/콜로 충분히 싸고, 값은 갱신되므로 쌓아두면 오히려 낡는다.
> 검증 파이프라인이 표를 특정한 뒤 그 시점에 조회하는 것이 정확성·비용 모두 우위.

> **원칙 2. 전수 크롤링이 아니라 수요 주도(claim-driven) 크롤링.**
> 전체 265,094표 × getMeta 2콜 = 약 53만 콜 ≈ 44시간/키. 그러나 지역통계가 60%이고
> 뉴스 claim의 대부분은 전국 단위 지표다. 뉴스가 실제로 묻는 표부터 보강한다.

> **원칙 3. 검색 API를 크롤러로 재활용한다.**
> `statisticsSearch.do` 1콜이 경로+차원값 요약+수록기간을 주므로,
> claim 지표명으로 검색 → 상위 후보 표만 getMeta 정밀 보강하는 2단 구조가 효율적.

## 3. 크롤링 레이어 설계

### Layer 0 — 커버리지 확장 (트리 크롤링 보완) : 1회성

기존 트리(MT_ZTITLE)에 누락 뷰를 추가 순회해 **표 목록(존재 여부)** 만 확보.

| 대상 | 방법 | 예상 비용 |
|---|---|---|
| 국제 `MT_RTITLE` | 빈 parentListId부터 BFS | 소규모 (수천 콜) |
| 북한 `MT_BUKHAN` | 〃 | 소규모 |
| e-지방지표 `MT_GTITLE01` | 〃 후 **table_key로 dedup** (주제별과 중복 가능성 큼) | 소규모 |
| 기관별 `MT_OTITLE` | 후순위 — 181개 기관 뷰는 주제별과 중복이 많아 dedup 후 잔여만 | 중간 |

산출물: `kosis_table_tree.json`에 뷰 태그를 붙여 병합 (`vw_cd` 필드 추가).

### Layer 1 — 검색 문서용 메타 보강 : claim-driven 우선순위

표당 `getMeta ITM` + `getMeta PRD` = **2콜**. 우선순위 큐:

| Tier | 대상 | 선정 방법 | 규모 추정 | 비용 |
|---|---|---|---|---|
| **A** | 뉴스가 실제 묻는 표 | claims_v1의 지표명 1,000여 종 → `statisticsSearch.do` 상위 10 후보 표 | 수천~1만 표 | 검색 1콜/지표 + 2콜/표 → **2~3시간** |
| **B** | 전국 단위 주제별 표 | MT_ZTITLE 중 '지역통계' 대분류 제외 | ~10.7만 표 | 21.4만 콜 ≈ **18시간/키** (팀 분산 시 ÷N) |
| **C** | 지역통계·기관별·국제·북한 | 잔여 전부 | ~15.8만 표 | 필요 시에만 (지역 claim 비중이 낮음) |

Tier A가 끝나면 곧바로 검색·검증 파이프라인이 돌 수 있고, B는 배경에서 채운다.

### Layer 2 — 검증 보조 메타 : 확정 표만

claim ↔ 표 매핑이 확정된 표에 한해 `getMeta CMMT`(시계열 단절 주석) 1콜 추가.
- 이유: "충남 2016↔2017 비교 불가" 같은 주석은 **증감률 claim 검증의 함정**을 막아준다.
- 전체 표에 미리 돌릴 필요 없음 — 매핑 확정 표는 수백~수천 개 수준.

### Layer 3 — 수치 조회 : 크롤링 아님, 런타임 on-demand

검증 실행 시 `statisticsParameterData.do`로 해당 셀·시점만 조회.
- 증감률 claim이면 두 시점(`startPrdDe`/`endPrdDe`)을 한 콜에 요청 (실측: 3개년 1콜)
- 응답의 `LST_CHN_DE`(최종갱신일)를 검증 결과에 함께 기록 → 재현성 확보

## 4. 실행 순서와 예산 (분당 200콜/키 기준)

```text
[0] probe (완료) ──────────────── 15콜, 즉시
[1] Layer 0: 누락 뷰 트리 확장 ── 1~2시간, 1키
[2] Layer 1-A: claim-driven 보강 ─ 2~3시간, 1키   ← 이것만 끝나도 파이프라인 가동
[3] Layer 1-B: 전국 주제별 전체 ── 18시간/키, 팀 N키 분산 시 18/N 시간
[4] Layer 2: 확정 표 CMMT ─────── 검증 단계에서 수시
[5] Layer 3: getData ──────────── 런타임 on-demand (크롤링 아님)
```

기존 자산 재활용: `kosis_meta_enricher.py`(체크포인트·재개·분산 병합)가 Layer 1 실행기,
`kosis_tree_crawler.py`에 뷰 파라미터만 추가하면 Layer 0 실행기가 된다.

## 5. 하지 않기로 한 것 (실측 근거)

| 후보 | 안 하는 이유 |
|---|---|
| `getMeta NCD` 전수 | 표당 459 rows·51KB — 갱신일은 getData 응답의 `LST_CHN_DE`로 충분 |
| `getMeta UNIT` | err 30(데이터 없음) 빈번, ITM 응답의 `UNIT_NM`이 이미 단위를 줌 |
| 수치(getData) 전수 적재 | 0.3초/콜로 on-demand가 더 싸고, 적재본은 갱신 시 낡음 |
| MT_OTITLE 181개 기관 전수 | 주제별 뷰와 중복 다수 예상 — dedup 후 잔여만 후순위 |
| 표 화면 Selenium 렌더링 | getMeta ITM이 같은 코드값을 공식 API로 반환 (이미 대체 완료) |
