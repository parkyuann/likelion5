### 1. 데이터 모델 — 4개 스키마
Claim ──1:N── ClaimObservation        (주장 1개 안의 다중 수치)
  │
  └──N:M── ClaimTableMapping ──── KOSISTable   (벡터DB 적재 대상)
              (후보·점수·정렬 결과)

스키마 <br>
- claim
    - 역할: 무엇을 주장했는지 + 검색 키
    - 핵심 필드: indicator_norm, population_norm, claim_class, source_scope, predicted_tbl_nm/predicted_path
- claimobservation
    - 역할: 주장 내 수치 1개
    - 핵심 필드: value_num, unit_norm, period, dimension, relation_type, sequence
- claimtablemapping
    - 역할: claim ↔ 표 후보
    - 핵심 필드: observation_id(신규), table_key, dense_score/sparse_score/reranker_score, matched_dimensions/matched_period, status, is_gold
- kosistable
    - 역할: 표 메타+문서
    - 핵심 필드: tbl_name, category_path, dimensions/items(document_text에 포함), period_types, units, version_status


### 2. 파이프라인 - 2트랙
════ 오프라인 (색인, 가끔 1회) ════════════════════════════════

kosis_table_tree.json
  └ build_kosis_catalog.py
      └ document_text = tbl_name + path + 차원명 + 항목명   ← 보강
          └ kosis_indexer.py
              ├ HCX Embedding v2 → dense
              ├ BM25 → sparse
              └ metadata(org_id, period_types, dimensions, units, version_status)
                  └ Qdrant 컬렉션 upsert


════ 온라인 (기사 1건) ═══════════════════════════════════════

raw data(기사)
 │
 ├ 1차 후보군   claim_extractor.py (규칙 기반 문장 후보)
 │
 ├ 2차 후보군   HCX 스키마화 → Claim + ClaimObservation
 │              + claim_normalizer 정규화
 │              + validate_claim() 스키마 게이트         ← 위반 차단
 │
 ├ 사전 필터    claim_class=집계통계 & source_scope=KOSIS등재?
 │              (탈락분은 사유 로깅 = 감사 가능)          ← 소프트 로깅
 │
 ├ HyDE         HCX가 predicted_tbl_nm / path 생성
 │
 ├ 하이브리드 검색  ┌ ① predicted_tbl_nm 임베딩 검색 ┐
 │  (Recall 방어)   ┤ ② 정규화 원주장 임베딩 검색     ├ 후보풀 합집합 N개
 │                  └ ③ 지표어 BM25 검색             ┘   → metadata 프리필터
 │
 ├ 리랭커        BGE-reranker → top K
 │              (mapping에 dense/sparse/reranker_score 기록)
 │
 ├ 차원·시점 정렬  observation별 → 표의 (항목·시점·차원) 매핑
 │                → ClaimTableMapping.matched_* 채움
 │
 ├ KOSIS API     선택 표의 셀 조회 (observation 개수만큼)
 │
 ├ 결정론적 검증  change_type별 계산 + 근사 오차 규칙
 │              → list_alignment_status (ALIGNED/COUNT_MISMATCH/…)
 │
 └ LLM 설명      확정 수치·시점·출처만 근거로 인용형 생성

### 4. 측정 지점 (설계에 내장)
- 2차 후보군
    - 지표: claim_class F1/파싱 실패율
    - 자산: data/labeling/*, validate_claim()

- 사전 필터
    - 지표: 정밀도/재현율(오탐 감사)
    - 자산: 탈락 로그

- 검색
    - 지표: Recall@N (정답 표가 후보에 있는지)
    - 자산: create_retrieval_eval_set.py

- 리랭커
    - 지표: Recall@K, MRR(단독 vs +리랭커)
    - 자산: mapping 점수

- 검증
    - 지표: ALIGNED 정확도
    - 자산: gold 라벨

착수 순서: ① Recall@N 골드셋 → ② 표 문서화+색인 → ③ 하이브리드 검색 → ④ 리랭커 비교 → ⑤ 정렬·검증 → ⑥ 설명 생성.
