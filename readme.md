# 연구계획서

* Background & Baseline  
  * 기존에 연구들은 이 문제, 혹은 유사 문제에 대하여 어떻게 접근하였는가?(논문 리서치. 단, 논문 리뷰는 생략합니다)  
    * 정치적 담화에서 검증 가치가 있는 사실적 주장을 자동으로 식별하는 인공지능 플랫폼인 클레임버스터([https://ranger.uta.edu/\~cli/pubs/2017/claimbuster-kdd17-hassan.pdf?utm\_source=chatgpt.com](https://ranger.uta.edu/~cli/pubs/2017/claimbuster-kdd17-hassan.pdf?utm_source=chatgpt.com)) → 사실 검증이 필요한 문장을 선별하며, 검증 가치가 높은 주장 먼저 탐지  
    * 텍스트 근거 기반 사실 검증([https://aclanthology.org/N18-1074](https://aclanthology.org/N18-1074)) → 주장을 입력받아 관련 문서를 검색하고, 근거 문장을 선택한 뒤 주장을 지지, 반박, 판단 불가로 분류  
    * ClaimDB([https://aclanthology.org/2026.acl-long.1589/?utm\_source=chatgpt.com](https://aclanthology.org/2026.acl-long.1589/?utm_source=chatgpt.com)) / 입력된 글(Claim)을 이해하여 데이터베이스 구조에 맞는 SQL을 생성하고, 이를 통해 데이터베이스를 질의(Query)하여 결과를 기반으로 사실 여부를 판단   
    * 테이블 기반 사실 검증 ([https://iclr.cc/virtual\_2020/poster\_rkeJRhNYDH.html?utm\_source=chatgpt.com](https://iclr.cc/virtual_2020/poster_rkeJRhNYDH.html?utm_source=chatgpt.com)) 자연어 주장과 표를 비교하여 참과 거짓 판정(부드러운 언어적 형태와 딱딱한 상징적 형태를 동시에 추론할 수 있는 더 정교한 아키텍처의 필요성 시사)기존 연구의 한계점  
    * 표 데이터와 비교하여 수치적 주장 참/거짓 판별 모델 매커니즘([https://openreview.net/forum?id=xE8rrv9yuG0](https://openreview.net/forum?id=xE8rrv9yuG0))   
    * wikipedia search API를 이용한 하나의 claim 검증([https://arxiv.org/abs/2109.00835](https://arxiv.org/abs/2109.00835))   
    * 검증 필요문장 탐지 모델([https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003331812](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003331812))  
    * 한국언론진흥재단의 뉴스 특화 BERT활용([https://ksbe-jbe.org/\_common/do.php?a=current\&b=11\&bidx=4209\&aidx=46480](https://ksbe-jbe.org/_common/do.php?a=current&b=11&bidx=4209&aidx=46480))  
    * 생성형 AI 기반 한국어 가짜뉴스 데이터 셋 구축 및 탐지 모델 비교 연구 ([https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003286169](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003286169))

* Proposed Method  
  * Problem Definition  
    * 어떤 task를 선택했는가?  
      \- AI 기반 뉴스 사실검증 시스템 (뉴스 기사에 포함된 수치 기반 주장을 구조화하고, KOSIS API를 활용하여 해당 주장의 일치 여부를 판정하는 주제)  
    * 구체적으로 어떤 문제를 해결하려고 하는가?  
      1\. 수치적 주장 탐지 및 검증  
      2\. 증거 기반 설명 생성  
      3\. 수치 또는 주장이 아닌 뉴스에 대해서도 진위여부 분류  
    * 왜 이 문제가 중요한가? (응용 맥락 포함)  
      1\. 거짓된 정보가 전달되는 것을 방지  
      2\. 해당 프로젝트는 단순한 잘못된 수치 구조를 파악하는 것에 국한되지 않습니다. 뉴스 기사와 공식 통계 사이의 이미와 통계적인 조건을 연결하고, 검증 과정을 구조화하여 제시함으로써 수치 정보의 해석 가능성과 검증 가능성을 높일 수 있습니다. 이를 통해 독자의 사실검증에 대한 부담을 줄이고, 통계 기반 보도의 정확성과 투명성을 향상시키며, 장기적으로는 언론과 공공정보에 대한 사회적 신뢰를 높이는 데에 기여할 수 있습니다.  
  * 어떤 아이디어를 적용할 것인가?  
    * **스키마 기반 사전 필터링** – `claim_class`, `source_scope` 두 축으로 먼저 문장을 분류하고, 이 조합이 `집계통계 x KOSIS계열`일 때만 KOSIS 조회 시도  
    * **임베딩 \+ 리랭커 기반 통계표 매핑** – 기사 주장을 고정된 스키마로 구조화하고, 임베딩 검색과 리랭커를 결합하여 적합한 통계표를 찾은 뒤, 기사와 통계표의 조건을 정렬한다. 실제 수치 비교는 LLM이 아니라 결정론적 계산 모듈이 수행하며, 최종 설명은 공식 근거와 계산 결과 안에서만 생성  
    * **근거 인용형 설명 생성** – RAG Reasoning 모델이 KOSIS 원자료(수치, 시점, 출처)를 프롬프트에 넣어 “어떤 표의 어떤 값을 근거로 판정했는지”를 설명에 명시, 후보 근거 비교 및 누락된 조건을 확인하며 추가 검색 필요 여부 판단  
    * **근사 표현 허용 오차 규칙** – “3명 중 1명” 같은 반올림식 서술을 다루기 위한 오차 허용 기준을 판정 로직에 명시

  * 채용한 아이디어가 baseline 대비 무엇이 다른가?  
    \- **검증 대상 판별**:   
    `claim_class / source_scope` 사전 필터링으로 조회 전 스크리닝  
    \- **표 매핑**:   
    임베딩 유사도 검색 \+ 리랭커  
    \- **판정 근거**:  
    KOSIS 원자료 인용 \+ 근사 오차 규칙 적용

    판단불가를 “KOSIS 밖(구조적)” vs “매칭 실패(개선 가능)”으로 구분

  * 왜 효과가 있을 것으로 예상하는가?  
    * 임베딩 모델과 리랭커를 결합한 검색은 단독적인 임베딩 모델 활용 검색보다 정확도를 향상시킬 것이다.

    * 오차 허용 규칙을 만들어 근사 표현의 오차를 잡아낼 수 있을 것이다.

# 데이터 특성

## 뉴스 데이터

1. **헤더 및 푸터 잔재 → 전처리 필요**

## 통계표

1. **판단이 불가하거나 주장이 아닌 기사도 존재**  
   ex)   
   국정자원 화재 복구율 25.8% → 40.5%: 진짜 수치지만 출처가 중앙재난안전대책본부이고, 정기 통계가 아닌 일회성 사고 대응 중 나오는 임시 집계라 KOSIS에 데이터 존재 X

   “쿠팡에 따르면 CIC가 확보, 운영하고 있는 데이터센터는 모두 서울을 비롯한 수도권에 위치하고 있으며, 최첨단 인프라를 갖추고 있다.”는 쿠팡의 데이터센터 위치를 설명하는 기사로, 수치도 주장도 아님  
2. **통계표 이름이 뉴스의 표현과 상당히 다름**  
   “물가” 하나가 소비자물가조사/생산자물가조사/농가판매및구입가격조사/산지쌀값조사 등으로 세분화. 뉴스가 “쌀값”이라고만 쓰면 산지가격인지 소비자가격인지부터 판단해야 표를 특정할 수 있음  
3. **트리 깊이가 일정하지 않음**  
   어떤 경로는 2단계 만에 조회 가능한 표가 나오고, 어떤 경로는 4\~5단계까지 내려가야 함. API 응답에 TBL\_ID가 있으면 조회 가능. LIST\_ID만 있으면 더 내려가야 함.  
4. 표 이름이 시기별로 갈라짐  
   산지쌀값조사 안에 산정 방식이 다른 두 표가 공존 \- 뉴스 시점에 맞는 버전을 골라야 함  
5. KOSIS 밖 판단불가  
   “정부조직 개편(19부→6처)” 주장이 혹시 놓친 표가 있는지 “정부·재정” 대분류 22개 하위 항목을 전부 확인했으나 없음 \- 국세·병무·국가채무·공무원인사 통계는 있어도 “정부 조직 구조” 자체를 다루는 표는 없음. 법령(정부조직법) 영역이지, 통계청 집계 대상이 아님을 확인

### **뉴스 주장 추출 스키마**

**핵심 스키마 필드**: `claim_text`, `indiccator_raw`, `population`, `value`, `unit`, `change_type`(증감률/증감폭/순위/비교/단순수치), `time_ref / time_compare`, `is_index`, `source_org_raw` 등

**사전 분류 필드(KOSIS 조회 전 필터링용)**: `claim_class`, `source_scope`, `verifiability_prefilter`

`claim_class` 9종:

- 검증 시도 대상: 집계통계(KOSIS계열 출처일 때만)  
- 판단불가: 개별사례 · 전망예측 · 목표계획 · 법령제도 · 사고대응임시통계(재난·사고 임시 집계) · 여론조사  
- 대상 외(주장 자체가 아님): 해석수사(과장 표현 등) · 통계조사안내(조사 제도 설명) · 정정보도(오류 정정 공지)

→ 37건 표본에서 “검증시도”로 분류된 비율 : 약 25\~30%; “판단불가가 상당 비중일 것”이라는 예상과 일치하는 방향. 나머지는 **출처가 KOSIS 계열이 아니거나**(민간기관·해외기관·타공식기관), **미래지향적**(전망·목표)이거나, **애초에 검증 대상 주장이 아니었음**(개별사례·안내·정정)

**“판단불가”의 두 가지 다른 원인 구분:**

1. KOSIS 안에 있는데 못 찾은 case \- RAG/임베딩 기반 검색으로 개선 가능(실전2의 “통계표 매핑” 도구가 다룰 영역으로 판단  
2. KOSIS 자체에 데이터가 없는 것 \- 검색을 아무리 잘해도 못 찾음. 이 프로젝트 범위(‘검증은 KOSIS 통계를 기준으로 수행) 밖. 지금까지 확인한 판단불가 사례는 재검증 결과 전부 이 유형에 해당

**구조적으로 새로 발견한 이슈**  
“문장 1개 \= 클레임 1개”라는 가정이 나열형 문장에서 깨짐(예: “17만 1000명, 16만 6000명, 31만 2000명… 7\~9월 월별 취업자 수”).  
실전2 추출기 설계 시 문장 단위가 아니라 수치 토큰 단위 후처리가 필요할 수도 있음

**검증 가능한 문장의 비율과 레이블에 따라 상이한지**  
정제된 본문 2,706건 전체를 대상으로 “수치·비교 표현”에 해당하는 문장의 비율 계산

| 레이블 | 기사 수 | 전체 문장 | 숫자 포함 문장 | 숫자+비교표현 문장 | 기사당 평균 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| False(키워드 X) | 197 | 3,402 | 46.4% | 7.3%(248개) | 1.3개 |
| True(키워드 O) | 2,500 | 50,242 | 52.7% | 21.0%(10,542개) | 4.2개 |

**True 레이블이 False보다 “수치+비교표현” 밀도가 약 3배 높다** – 단순 숫자 포함 비율은 큰 차이가 없지만 비교/증감 표현이 같이 나오는 문장으로 범위를 좁히면 격차가 뚜렷해짐 → 키워드 필터링이 실제로 “통계 보도 밀도가 높은 기사”를 걸러내는 효과가 있었다는 의미
