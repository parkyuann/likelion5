# 벡터DB 조사

## 종류

### 1. Qdrant (현재) 
- ANN 알고리즘을 사용

- Rust 기반 전용 벡터DB. 최근 RAG 프로젝트의 사실상 기본값.
#### 장점
- 로컬 / 서버 둘다 가능
- payload 필터링 강력 (필터를 걸어도 인덱스 성능 유지)
- 포인트당 벡터 여러 개 저장 가능
- 양자화 지원
#### 단점
 - BM25 토큰화 직접 해야함(한국어 형태소 분석 미제공)
 - GPU 미지원

### 2. FAISS 
Meta가 만든 유사도 검색 라이브러리 (파이썬 라이브러리)
#### 장점
#### 단점
1. payload 필터링이 사라짐 (FAISS는 벡터와 정수 ID만 암)
2. 배포 단계에서 서버를 직접 만들어야 함 

### 3. Milvus
- 대규모 분산 아키텍처, 스토리지-컴퓨트 분리
#### 장점
- 수십억 벡터급 확장성
- 인덱스 종류가 다양
- GPU 인덱싱 지원
#### 단점
- 구성 요소가 많아 운영 복잡
- 소규모엔 오버킬임

### 4. Weaviate
- 스키마 기반, 하이브리드 검색이 강점
#### 장점
- BM25+벡터 하이브리드가 내장
